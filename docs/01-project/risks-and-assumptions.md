## 2. Допущения

- A-01. Маршрут строится до конкретной точки подключения ОКС; геометрия ОКС
  не влияет на маршрут (протокол).
- A-02. `upstream_object_id` образует корректную цепочку до источника без
  циклов; сервис обязан уметь сообщить о нарушениях.
- A-03. Расход ОКС задан готовым (`flow_tph`); он может передаваться на
  `oks_future` или на точке подключения (как в образце) — связывание по
  доступным атрибутам.
- A-04. Единица длины входных координат после преобразования в EPSG:32637 — метры.
- A-05. Значения `restriction_type` соответствуют типам из ТП или их алиасам;
  обработка — по конфигурации.
- A-06. Все ОКС в конкурсном наборе технически подключаемы; неполный результат —
  резервный сценарий; неподключение допускается при дороговизне трассы.
- A-07. Один источник; мощность не ограничивает.
- A-08. Существующая сеть не требует изменения трассы при реконструкции;
  её геометрия не проверяется (протокол).
- A-09. Часовой пояс/локаль не влияют на расчёт; числа считаются в double.
- A-10. Выгрузка и загрузка выполняются на одном сервере; сетевые ограничения
  не учитываются (кроме размеров файлов).
- A-11. Сервис работает офлайн, без внешних сервисов и агентов; разворачивается
  в единственном экземпляре (протокол).
- A-12. Расстояния округляются в большую сторону при незначительном отклонении
  (протокол).
- A-13. При наложении зон нескольких препятствий применяется максимальный
  коэффициент `Kспец`; один спецучасток на весь участок, без перемножения
  (протокол; ждёт окончательного подтверждения).
- A-14. UI не требуется; корректность GeoJSON — ключевой показатель (протокол).

## 3. Зависимости

- Конкурсный набор данных (полный) — от организаторов.
