# Требования

Источники: `source/2. ДИТ.pdf` (кейс), `source/Техническое  приложение ЛЦТ v2.docx`
(ТП v2, актуально), `source/Разъяснения по вопросам ЛЦТ.docx` (разъяснения) и
`source/Протокол встречи 16.09.2026.md` (уточнения организатора).

> При расхождении приоритет: **ТП v2** → разъяснения → протокол → PDF.
> Изменения относительно прежней редакции вызваны ТП v2 и разъяснениями
> 18.09.2026 (помечены «(v2)»).

## 1. Функциональные требования (FR)

### 1.1. Ввод и подготовка данных

| ID | Требование | Источник |
|----|-----------|----------|
| FR-01 | Принимать один совмещённый файл GeoJSON типа `FeatureCollection` | ТП 1 |
| FR-02 | Геометрия на входе — WGS 84 (EPSG:4326) | ТП 1 |
| FR-03 | Расчёты длин, расстояний и габаритов — в EPSG:32637 | ТП 1 |
| FR-04 | Базовые типы: `source`, `heat_network`, `heat_chamber`, `oks_connection_point`, `restriction` | ТП 1.1 |
| FR-05 | Обязательные атрибуты: все — `id`, `object_type`; `heat_network` — `diameter`; `oks_connection_point` — `flow_tph`; `restriction` — `restriction_type` | ТП 1.1 |
| FR-06 | Для `restriction` учитывать `restriction_type` | ТП 1.1 |
| FR-07 | Потоковая обработка; вход до 3 ГБ, реально 2–3 ГБ | PDF 3.2, протокол |
| FR-08 | Валидация и диагностика; невалидная геометрия → диагностическая ошибка | PDF 8, протокол |
| FR-09 | Каждая `oks_connection_point` — самостоятельная цель со своим `flow_tph`; связь с полигоном ОКС отдельным ID не задаётся | ТП 1.1; разъяснение 4 |
| FR-11 | Тысячи объектов в масштабе города | протокол |
| FR-14 | ID входных объектов — строковые **или** числовые; формат не интерпретируется | ТП 1 |

| FR-16 | Дополнительные типы `restriction` — как расширение (обязательны только типы таблицы 2) | ТП 1.2, 4; разъяснение 9 |
| FR-17 | Устаревшие/необязательные поля (`oks_future`, `oks_existing`, `upstream_object_id`, `flow_tph` у `heat_network`, `diameter` у `heat_chamber`) игнорировать, не падать | ТП 1.1 |

| FR-77 | Частичный результат и `unconnected_oks_ids`; неподключение только при отсутствии допустимого маршрута | ТП 2.5; разъяснение 15 |

### 1.8. Дополнительный режим с учётом глубины (не обязателен)

| ID | Требование | Источник |
|----|-----------|----------|
| FR-90 | Отдельный режим и отдельный набор вариантов; не объединяется с 2D; Z-координаты не требуются | ТП 5 |
| FR-91 | Обычная глубина 3,0 м, минимальная 0,7 м; максимальная и дискретный шаг не задаются | ТП 5; разъяснение 16 |
| FR-92 | Уклон ≤0,10 м/м; профиль спуск/постоянная/возврат; между близкими препятствиями допускается сохранять глубину | ТП 5 |
| FR-93 | `Kгл = 1 + 0,10·(h−3)` при `h > 3`, иначе 1; на уклоне — среднее; при пересечении уровня 3,0 м — `technical_node` и деление | ТП 5 |

> Реализовано в M4 (ADR-0073): режим `mode=2d|depth`, вертикальный пост-слой,
> `depth_start`/`depth_end`, `Kгл` в стоимости, техузлы границ профиля;
> интеграция в поиск пути — E9-05, профиль по путям дерева — E9-06.

## 3. Критерии оценки (для приоритизации)

Обязательные правила, затем подход, качество трассировки, эффективность,
техническая проработка, варианты и объяснимость, дополнительная ценность, питч.
Проверочный набор — отдельные выгрузки из рабочих систем, не переданный
конкурсный файл (разъяснение 17).
