# Ограничения

Все ограничения ниже обязательны, если не указано иное. Изменение
обязательных ограничений фиксируется ADR.

## 2. Технологические ограничения

- Геометрия на входе в EPSG:4326, расчёты — в EPSG:32637. Смешивать CRS
  в одном расчёте нельзя.
- Задача не сводится к точному полиномиальному решению: ограничения
  (общие стволы, степень камеры ≤4, предельная длина на диаметр,
  нелинейная стоимость) делают её NP-сложной. Используется эвристика
  (см. [algorithm.md](../03-architecture/algorithm.md)).
- Один линейный объект = пара подающего и обратного трубопроводов одного Ду.
- Полный гидравлический расчёт не выполняется; используются табличные
  пропускные способности и предельные длины.
- Реконструкция существующей сети и камер не выполняется; топология по
  `upstream_object_id` не требуется (ТП v2).
- Ду выбирается минимальным, удовлетворяющим и расходу, и предельной длине;
  предельная длина проверяется по непрерывным путям (ветви не суммируются).
- Угол поворота произвольный до 90°, без удорожания; удорожания поворотов и
  нестандартных углов нет.

## 3. Ограничения предметной области

- Источник один, ограничение мощности не учитывается.
- Существующая сеть используется только для выбора места присоединения;
  реконструкция не выполняется.
- Существующие коммуникации между собой пересекаются на одном уровне;
  взаимное положение не проверяется.
- Рельеф не учитывается (только в дополнительной задаче — условная
  горизонтальная поверхность Z=0).
- Геология и грунтовые воды не учитываются.
- Геометрия существующей сети не проверяется (протокол).
- Дана конкретная точка подключения (`oks_connection_point`); полигон ОКС —
  ограничение `oks`, не задающее маршрут напрямую, но непроходимое (ТП 2.2).
- Присоединение — только через тепловую камеру; отдельного `tie_in` нет.
- К камере ≤4 примыканий; существующая проходная линия занимает 2 примыкания.
- Минимум 0,7 м — это минимальное отклонение по глубине от пересекаемого
  препятствия; шага глубины 0,5 м в актуальном приложении нет (протокол).
- Близкие пересечения разрешено объединять в один подход без возврата на
  глубину 3,0 м; критерий близости уточняется (протокол).

## 4. Ограничения на данные (универсальность)

- Координаты, ID и конфигурацию набора запрещено фиксировать в коде (NFR-09).
- Сервис проверяется на отдельном наборе той же структуры.
- Правила ограничений должны быть конфигурируемыми: обязательны типы таблицы 2
  ТП v2, прочие — расширение (см. [risks-and-assumptions.md](risks-and-assumptions.md)).
- Идентификаторы входных объектов — строка или число; тип сохраняется в выводе
  (`unconnected_oks_ids`).

## 5. Ограничения процесса

- Ручное исправление построенной геометрии перед демонстрацией не допускается.
- Дополнительная задача по глубине не должна ломать обязательную 2D-часть.
- Сроки задаются вехами промежуточной и финальной сдачи
  ([roadmap.md](../04-delivery/roadmap.md)).

## 6. Риск устаревших версий

Java 11 и Spring Boot 2.6.3 — устаревшие (2022) платформы. Это осознанное
ограничение кейса. Следствия:
- часть новых библиотек несовместима; версии зависимостей подбираются
  с проверкой.
- Flyway из состава Spring Boot 2.6.3 (v8) не поддерживает PostgreSQL 18 —
  поэтому миграции БД на старте не используются (см. ADR-0005).
