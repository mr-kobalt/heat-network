# Анализ образца `source/data_example.geojson`

Файл проанализирован на этапе планирования. **Важно:** образец неполон
относительно ТП. Реализация следует ТП, а не образцу (риск R-01).

## 1. Состав файла

Всего **144** объекта, CRS — `urn:ogc:def:crs:OGC:1.3:CRS84` (WGS 84).

| `object_type` | Кол-во | Геометрия | Наблюдения |
|---------------|-------:|-----------|------------|
| `oks_connection_point` | 17 | Point | Есть `flow_tph`; нет `oks_id` |
| `restriction` | 88 | MultiPolygon | 85 `oks`, 1 `railway`, 2 `water`; 85 с `address` |
| `heat_network` | 29 | LineString | Только `diameter`; нет `flow_tph` и `upstream_object_id` |
| `heat_chamber` | 9 | Point | Нет `diameter` и `upstream_object_id` |
| `source` | 1 | Point | `name = ТЭЦ "ЗИЛ"` |
| `oks_future` | 0 | — | Отсутствует |
| `oks_existing` | 0 | — | Отсутствует |

Итого перспективный расход: **488,72 т/ч** (17 точек, от 4,08 до 76,27).
По таблице 4.1 суммарный расход потребовал бы Ду ≥ 400 мм.

Диаметры существующей сети: 300 мм (7), 400 мм (14), 500 мм (8).

## 2. География

- Долгота: 37.626269 … 37.658166; широта: 55.690915 … 55.705547.
- Примерный размер площадки: ~2,0 × 1,6 км (район Автозаводской улицы).

## 3. Расхождения со спецификацией

| № | Образец | ТП | Влияние |
|---|---------|----|---------|
| 1 | Нет `oks_future`/`oks_existing` | Обязательные типы | Нельзя отладить привязку точек и правила для существующих ОКС |
| 2 | `flow_tph` на `oks_connection_point` | `flow_tph` у `oks_future` | Модель привязки отличается |
| 3 | Нет `oks_id` у точек подключения | `oks_id` обязателен | Невозможно проверить связь точка↔ОКС |
| 4 | У `heat_network` нет `flow_tph`, `upstream_object_id` | Обязательны | Нельзя проверить топологию и реконструкцию |
| 5 | У `heat_chamber` нет `diameter`, `upstream_object_id` | Обязательны | Нельзя проверить реконструкцию камер |
| 6 | `id` — целые числа | Строки | Тип парсера должен быть терпимым/строковым |
| 7 | `restriction_type`: `oks`, `railway` | В таблице 5.1 иные имена | Нужны алиасы/конфиг (ADR-0009, Q-01, Q-02) |
| 8 | Нет специальных проходов (`road`, `gas_pipeline`, `power_cable`, `heat_network`) | Возможны в полном наборе | Спецпроходы на образце не проверить |

## 4. Топология (по геометрии)

- Концы линейных участков совпадают с координатами всех 9 камер —
  вероятно, сеть разбита в камерах.
- Координата источника не совпадает точно ни с одним концом линии —
  топология должна задаваться `upstream_object_id` (в образце отсутствует).
- Точки подключения удалены от ближайших узлов сети в среднем на ~235 м
  (от 21,5 до 412,8 м) — маршруты нетривиальны, есть что оптимизировать.

## 5. Выводы для разработки

1. Строить generic-парсер: терпимость к типам, алиасам и отсутствию
   необязательных полей, но диагностика обязательных.
2. Не использовать образец для проверки топологии/реконструкции до
   получения полного набора; подготовить синтетические фикстуры по ТП.
3. Правила ограничений — конфигурируемые, с дефолтами для `oks`/`railway`.
4. Для отладки маршрутизации образца достаточно (есть ОКС-точки, сеть,
   камеры, источник и запретные зоны).

## 6. Уточнения по протоколу встречи 16.09.2026

- Датасет изменён: даётся **конкретная точка подключения**, а геометрия ОКС
  на маршрут не влияет. Поэтому отсутствие `oks_future`/`oks_existing`
  и наличие `flow_tph` на точках подключения — ожидаемо, а не дефект образца.
- Конкурсный набор — **тысячи объектов** в масштабе города; образец мал (144),
  но структурно показателен для отладки маршрутизации.
- Часть сведений (критическая инфраструктура, ИБ) урезана.
- Атрибуты сети (`flow_tph`, `upstream_object_id`) и `diameter` камер в образце
  отсутствуют; для проверки реконструкции нужен полный набор или синтетические
  фикстуры по ТП.
- Невалидная геометрия на входе → диагностическая ошибка (не «молчаливый» обход).
