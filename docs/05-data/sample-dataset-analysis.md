# Анализ скорректированного набора `source/Датасет скорректированный.geojson`

Набор получен 18.09.2026 вместе с ТП v2 и разъяснениями. Это **основной**
набор для отладки и тестов; `source/data_example.geojson` — исторический.
Реализация следует ТП v2, а не набору (риск R-01, NFR-09).

## 1. Состав файла

Всего **144** объекта, CRS — `urn:ogc:def:crs:OGC:1.3:CRS84` (WGS 84).

| `object_type` | Кол-во | Геометрия | Наблюдения |
|---------------|-------:|-----------|------------|
| `oks_connection_point` | 17 | Point | Только `id`, `object_type`, `flow_tph` |
| `restriction` | 88 | MultiPolygon | 85 `oks`, 2 `water`, 1 `railway`; 85 с `address` |
| `heat_network` | 29 | LineString | Только `id`, `diameter`; нет `flow_tph`/`upstream_object_id` |
| `heat_chamber` | 9 | Point | Только `id`, `object_type` (нет `diameter`) |
| `source` | 1 | Point | `name = ТЭЦ ЗИЛ` |
| `oks_future` / `oks_existing` | 0 | — | Не используются (ТП v2) |

- Идентификаторы — целые числа (ТП допускает строковые/числовые).
- Суммарный расход точек подключения: **488,72 т/ч** (от 4,08 до 76,27).
- Диаметры существующей сети: 400 мм (22), 500 мм (6), 300 мм (1).

## 2. География

- Долгота: 37.626269 … 37.658166; широта: 55.690915 … 55.705547.
- Ориентировочно ~2,0 × 1,6 км (район Автозаводской улицы).

## 3. Соответствие ТП v2

| Аспект | Набор | ТП v2 | Комментарий |
|--------|-------|-------|-------------|
| Типы объектов | Базовые 5 типов | Базовый состав | Полное соответствие |
| ОКС | Полигоны `restriction=oks` | ОКС как ограничение | Каждая точка — самостоятельная цель |
| `heat_network` | `id`, `diameter` | `id`, `object_type`, `diameter` | Соответствует |
| `heat_chamber` | `id` | `id`, `object_type` | Соответствует |
| Точка подключения | `flow_tph` | `flow_tph` | Соответствует |
| ID | целые числа | строка/число | Парсер должен сохранять тип |

Расхождения прежней редакции (отсутствие `oks_future`, `flow_tph` сети,
`upstream_object_id`, `diameter` камер) **сняты**: они не входят в базовый
состав v2, а реконструкция не выполняется.

## 4. Топология и геометрия

- Существующая сеть — цепочка из 29 линейных участков; у 9 камер степень 2
  (проходная линия), два конца цепочки —degree 1.
- Каждая из 9 камер лежит точно на концах двух участков → проходная линия
  занимает **2 примыкания** (разъяснение 12).
- Источник — точка; топология по `upstream_object_id` в наборе отсутствует и
  не требуется.
- Все 17 точек подключения лежат **внутри** своего `oks`-полигона (по одной
  на точку); расстояние до ближайшей границы ~1–9 м. Поэтому критичен
  финальный прямой участок от границы полигона до точки (ТП 2.2).
- Точки подключения удалены от ближайших участков сети в среднем на ~230–420 м
  (0,0003–0,0066° по долготе) — маршруты нетривиальны.

## 5. Выводы для разработки

1. ОКС-полигоны обрабатывать как запретные ограничения `oks` с финальным
   коридором к целевой точке.
2. Присоединение строить только через камеру (существующую с учётом примыканий
   либо новую); `tie_in` в выводе не формировать.
3. Реконструкцию и upstream-топологию не реализовывать.
4. Предельную длину считать по непрерывным путям (ветви не суммировать).
5. Тип ID сохранять в `unconnected_oks_ids`; для тестов использовать этот набор.
6. Правила ограничений — конфигурируемые; `railway` — запрет.
