# Задача и проблема

- Новые ОКС подключают к существующей тепловой сети в плотной городской
  застройке; тысяч объектов, маршруты и точки врезки подбираются вручную.
- Нужен автоматический расчёт: место присоединения, трасса, общие стволы,
  ограничения, расходы и Ду, предельная длина, стоимость.
- Цель: за один запуск — корректный GeoJSON с несколькими объяснимыми
  вариантами, без ручной правки геометрии.

::: notes
Акцент на боли: ручной подбор даёт неоптимальные и невоспроизводимые решения.
Наши цели — корректность по ТП v2, универсальность и объяснимость.
:::

# Решение: что делает сервис

- Вход — один совмещённый GeoJSON (`source`, `heat_network`, `heat_chamber`,
  `oks_connection_point`, `restriction`); ОКС — ограничение `oks`.
- Выход — один GeoJSON: участки, камеры, технические узлы и сводки вариантов.
- **Headless** сервис, полностью **офлайн**; REST API + Swagger UI.
- Асинхронный расчёт, потоковая обработка (вход до 3 ГБ, выход до 500 МБ).

::: notes
Сервис без UI — оценивается корректность GeoJSON. Расчёт детерминированный,
без обращения к внешним сервисам.
:::

# Данные и конвейер

- Потоковый разбор GeoJSON (Jackson) без загрузки файла целиком в память.
- Диагностика входных данных: счётчики объектов, bbox, предупреждения;
  невалидная геометрия — понятная ошибка.
- CRS: вход WGS 84 (4326), расчёт в метрах (UTM 37N, 32637).
- Крупные наборы — пространственное партиционирование входа по тайлам.

::: notes
Потоковость — требование NFR-08 (вход 2–3 ГБ). Партиционирование включается
опцией `forest-partition-tile-m`; в единичном режиме baseline не меняется.
:::

# Алгоритм: grid-forest

- Единый поиск по сетке (`grid-forest`, ADR-0034):
  1. растровая сетка проходимости с учётом запретных буферов и спецзон;
  2. многоисточниковый Дейкстра от существующей сети;
  3. рост леса деревьев к точкам подключения ОКС.
- Поворот ≤90° — жёсткое ограничение; `Kспец` учитывается в цене шага.
- Общие стволы для нескольких ОКС; ветвления — только в камерах.

::: notes
Эвристика (задача NP-сложная), но подбор Ду и стоимость — точные.
Сетка — пространство поиска, а не дискретизация входной геометрии.
:::

# Алгоритм: топология и геометрия

- Присоединение — только через тепловую камеру: существующая (правило ≤10 м и
  свободные примыкания) либо новая; ≤4 примыканий (проходная линия = 2).
- `relink` — переприсоединение и перестройка топологии дерева.
- `refine` — углы ≤90°, упрощение, устранение самопересечений, выпрямление
  спецучастков.
- Оптимизация и слияние камер; выход ОКС — канонический `target → point`.

::: notes
Свой ОКС непроходим, кроме финального хвоста выхода. Самопересечения
проверяются и локально, и между деревьями (FR-29).
:::

# Гидравлика, стоимость, варианты

- Расход участка — сумма расходов подключённых через него точек.
- Подбор **минимального Ду**, одновременно удовлетворяющего расходу и
  предельной длине по непрерывным путям; Ду не убывает к присоединению.
- Стоимость: участки (`cнов(Ду)·Kгл·Kспец`), новые камеры, врезки в
  существующие камеры, штраф за неподключённые точки.
- До **трёх** содержательно разных вариантов, ранжирование по
  `S = 0,7·(C/25 млн) + 0,3·(L/100)`.

::: notes
Предельная длина — по каждому непрерывному пути, ветви не суммируются.
Произвольное завышение Ду не допускается (разъяснение 1).
:::

# Соответствие ТП v2

- Присоединение через камеру, отдельного `tie_in` нет.
- ≤4 примыканий; проходная линия занимает 2.
- Спецпроход — одним прямым участком, угол ≥45°, `Kспец` без перемножения.
- Финальный прямой участок в `oks`; Ду + предельная длина по путям;
  стоимость, штрафы, `S`, до трёх вариантов.
- **Реконструкция существующей сети и камер не выполняется** (ТП v2,
  разъяснение 14); текущие расходы и резерв существующей сети **не
  определяются** — это исключено актуальной редакцией ТЗ.

::: notes
Важно проговорить пункты 4 и 6 демонстрации из PDF: реконструкция и влияние на
существующую сеть в ТП v2 исключены, поэтому сервис их не считает — это не
пропуск, а соответствие текущим правилам.
:::

# Пространственные ограничения

- Правила по типам конфигурируемы (таблица 2 ТП v2), обязательные типы
  поддержаны; прочие — расширение.
- Запреты обходятся с минимальным расстоянием; `oks` — 5/7/9 м по Ду.
- Спецпроходы — один прямой участок; при наложении берётся максимальный
  `Kспец`.
- Строгий обход спецпроходов (опция): полоса непроходима, пересечение — через
  перпендикулярные «ворота».

::: notes
Правила и коэффициенты вынесены в конфигурацию (ADR-0009), не «зашиты» в код.
:::

# Дополнительный режим: глубина (M4)

- Отдельный режим (`mode=depth`) и отдельный набор вариантов.
- Глубина как атрибуты `depth_start`/`depth_end` (Z-координаты не нужны).
- Профиль спуск/полка/возврат, уклон ≤0,10 м/м; `Kгл = 1 + 0,10·(h−3)`.
- Технические узлы на границах профиля; учёт вертикальных габаритов
  коммуникаций.

::: notes
Текущая реализация — вертикальный пост-слой над 2D-маршрутом. Полная
перестройка маршрута с учётом глубины (ре-роутинг) — следующий шаг (E9-05).
Честно обозначить границу.
:::

# Качество и надёжность

- Быстрые тесты (секунды) + тег `slow` (эталонные прогоны, A/B).
- Инварианты ТП v2: самопересечения, углы, степень камер, канонический выход,
  ссылки узлов.
- Харнесс проверки произвольного набора (готовность к проверочному набору).
- Golden-baseline по показателю `S` на основном и OSM-наборе.

::: notes
Универсальность (NFR-09): сервис не привязан к конкретному набору; захардкоженных
координат/ID нет.
:::

# Границы применения и допущения

- Полный гидравлический расчёт (давление, потери, насосы) и мощность источника
  не моделируются.
- Реконструкция и текущие расходы существующей сети — вне модели (ТП v2).
- Рельеф, геология, грунтовые воды не учитываются; поверхность условная.
- Маршрутизация — эвристика: возможны неоптимальные, но допустимые решения.
- Неподключение — только при отсутствии допустимого маршрута.

::: notes
Честно назвать границы и допущения — это снижает вопросы жюри и показывает
понимание предметной области.
:::
