# Задача и проблема

- Новые ОКС подключают к существующей тепловой сети в плотной городской
  застройке; тысячи объектов, маршруты и точки врезки подбираются вручную.
- Нужен автоматический расчёт: место присоединения, трасса, общие стволы,
  ограничения, расходы и Ду, предельная длина, стоимость.
- Цель: за один запуск — корректный GeoJSON с несколькими объяснимыми
  вариантами, без ручной правки геометрии.

::: notes
Задача — подключить перспективные объекты капитального строительства к
существующей тепловой сети. Основная сложность — плотная городская застройка:
нужно выбрать точку врезки, проложить трассу, обойти ограничения, посчитать
расходы, диаметры и длину — и так для тысяч объектов. Сегодня это делается
вручную: долго, дорого и невоспроизводимо — два инженера могут получить разные
маршруты. Наша цель — за один запуск получить корректный, объяснимый и
воспроизводимый результат, без ручной правки геометрии.
:::

# Решение: что делает сервис

- Вход — один совмещённый GeoJSON (`source`, `heat_network`, `heat_chamber`,
  `oks_connection_point`, `restriction`); ОКС — ограничение `oks`.
- Выход — один GeoJSON: участки, камеры, технические узлы и сводки вариантов.
- **Headless** сервис, полностью **офлайн**; REST API + Swagger UI.
- Асинхронный расчёт, потоковая обработка (вход до 3 ГБ, выход до 500 МБ).

::: notes
Сервис принимает один совмещённый GeoJSON со всеми объектами: источник,
существующая сеть и камеры, точки подключения ОКС и ограничения. На выходе —
тоже один GeoJSON: участки новой сети, новые камеры, технические узлы и сводки
по вариантам. Сервис полностью headless, без интерфейса, и работает офлайн —
никаких обращений к внешним сервисам. Управление через REST API, документация —
Swagger. Расчёт асинхронный и потоковый: вход до трёх гигабайт, выход до
пятисот мегабайт.
:::

# Данные и конвейер

- Потоковый разбор GeoJSON (Jackson) без загрузки файла целиком в память.
- Диагностика входных данных: счётчики объектов, границы набора, предупреждения;
  невалидная геометрия — понятная ошибка.
- CRS: вход WGS 84, расчёт в метрах (UTM 37N).
- Крупные наборы — пространственное партиционирование входа по тайлам.

::: notes
Входной файл читаем потоково, не загружая его целиком в память — это
принципиально для больших наборов. Сразу собираем диагностику: сколько объектов
каждого типа, границы набора, список предупреждений. Невалидная геометрия даёт
понятную ошибку, а не падение сервиса. Все расчёты идут в метрах. Для очень
больших наборов есть пространственное партиционирование: вход режется на тайлы,
и каждый считается независимо. На небольших наборах этот режим выключен, поэтому
результат не отличается.
:::

# Поиск пути: единый лес

- Единый поиск по сетке проходимости:
  1. растровая сетка с учётом запретных буферов и специальных зон;
  2. многоисточниковый поиск кратчайших путей от существующей сети;
  3. рост леса деревьев к точкам подключения ОКС.
- Поворот не больше 90° — жёсткое ограничение; стоимость спецпрохода — в цене шага.
- Общие стволы для нескольких ОКС; ветвления — только в камерах.

::: notes
Мы не перебираем пары точек, а растим сеть целиком. Сначала строим сетку
проходимости: клетки, попавшие в запретные зоны, блокируются. Затем запускаем
поиск сразу из всех клеток существующей сети — это многоисточниковый вариант
Дейкстры — и от неё «растём» деревьями к точкам подключения. По ходу жёстко
соблюдаем ограничение: угол поворота не больше девяноста градусов, а стоимость
специального прохода учитывается прямо в цене шага. Несколько близких объектов
естественно объединяются в общий ствол, а ветвления допускаются только в
камерах.
:::

# Топология и геометрия

- Присоединение — только через тепловую камеру: существующая (не дальше 10 м и
  со свободными примыканиями) либо новая; не больше четырёх примыканий
  (проходная линия занимает два).
- Переподключение перестраивает топологию дерева.
- Доводка геометрии: углы до 90°, упрощение, устранение самопересечений,
  выпрямление специальных участков.
- Оптимизация и слияние камер; выход к объекту — канонический, два отрезка.

::: notes
После роста приводим результат в порядок. Присоединение всегда идёт через
тепловую камеру: если рядом есть существующая и у неё есть свободные примыкания,
используем её, иначе создаём новую. К камере может примыкать не больше четырёх
линейных участков, причём существующая проходная линия занимает два примыкания.
Затем переподключение перестраивает топологию дерева, а доводка геометрии
убирает мелкие изломы, выпрямляет специальные участки и устраняет
самопересечения — и внутри одного дерева, и между разными. Выход к объекту
всегда канонический и состоит ровно из двух отрезков.
:::

# Гидравлика, стоимость, варианты

- Расход участка — сумма расходов подключённых через него точек.
- Подбор **минимального Ду**, одновременно удовлетворяющего расходу и
  предельной длине по непрерывным путям; Ду не убывает к присоединению.
- Стоимость: участки (`cнов(Ду)·Kгл·Kспец`), новые камеры, врезки в
  существующие камеры, штраф за неподключённые точки.
- До **трёх** содержательно разных вариантов, ранжирование по
  `S = 0,7·(C/25 млн) + 0,3·(L/100)`.

::: notes
Расход каждого участка — сумма расходов всех точек, которые через него
подключаются. Диаметр подбираем минимальным, который одновременно выдерживает и
расход, и предельную длину, причём длину проверяем отдельно по каждому
непрерывному пути, а не по сумме ветвей. Диаметр не уменьшается по направлению к
точке подключения. Стоимость складывается из участков, новых камер, врезок в
существующие камеры и штрафа за неподключённые точки. На выходе — до трёх
содержательно разных вариантов, отсортированных по показателю S: чем меньше S,
тем лучше вариант.
:::

# Пространственные ограничения

- Правила по типам ограничений настраиваются: запрет или специальный проход,
  минимальное расстояние, допустимый угол, коэффициент.
- Запреты обходятся с нужным зазором; отступ от ОКС — 5, 7 или 9 м по Ду.
- При наложении специальных проходов берётся максимальный коэффициент,
  без перемножения.
- Включаемая строгая проверка: движение вдоль препятствия запрещено,
  пересечение — только поперёк.

::: notes
Пространственные ограничения берём из конфигурации: для каждого типа задано,
это запрет или специальный проход, минимальное расстояние, допустимый угол и
коэффициент стоимости. Обязательные типы поддержаны, остальные можно добавить
без изменения кода. Запреты обходим с необходимым зазором; отступ от ОКС — пять,
семь или девять метров в зависимости от диаметра. При наложении нескольких
специальных проходов берём максимальный коэффициент, без перемножения. Есть
включаемая опция строгой проверки: движение вдоль препятствия запрещено, а
пересечение возможно только под прямым углом, через «ворота».
:::

# Дополнительный режим: глубина

- Отдельный режим и отдельный набор вариантов.
- Глубина хранится атрибутами начала и конца участка; Z-координаты не нужны.
- Профиль спуск/постоянная глубина/возврат, уклон не больше 0,10 м/м;
  `Kгл = 1 + 0,10·(h−3)`.
- Технические узлы на границах профиля; учитываются вертикальные габариты
  коммуникаций.

::: notes
Дополнительно мы реализовали режим с учётом глубины. Он включается отдельно и
даёт отдельный набор вариантов. Глубина хранится атрибутами начала и конца
участка, без Z-координат. Сервис строит профиль: спуск, участок постоянной
глубины и возврат, с ограничением уклона; учитывает вертикальные габариты
коммуникаций, а на границах профиля ставит технические узлы. Сейчас это
вертикальная надстройка над плоским маршрутом; следующий шаг — научить
маршрутизатор сразу учитывать глубину и при необходимости менять трассу.
:::

# Границы применения и допущения

- Полный гидравлический расчёт (давление, потери, насосы) и мощность источника
  не моделируются.
- Реконструкция и текущие расходы существующей сети — вне модели по ТП v2.
- Рельеф, геология, грунтовые воды не учитываются; поверхность условная.
- Маршрутизация — эвристика: решения допустимые и объяснимые, но не
  гарантированно оптимальные.
- Неподключение — только при отсутствии допустимого маршрута.

::: notes
Честно обозначу границы. Мы не делаем полный гидравлический расчёт — давление,
потери напора, насосы — и не считаем мощность источника. Реконструкция и
текущие расходы существующей сети вне модели по актуальным правилам. Рельеф,
геология и грунтовые воды не учитываются, поверхность считается условно
горизонтальной. Маршрутизация — эвристика: решения допустимые и объяснимые, но
не гарантированно оптимальные. Точка попадает в неподключённые только тогда,
когда допустимого маршрута действительно нет.
:::

- Интеграция глубины в поиск пути: перестроение трассы с учётом глубины.
- Выгрузка состояния сетки в базу для сверхкрупных наборов.
- Расширение набора проверочных тестов и тонкая настройка эвристик.
- Развитие визуализатора и отчётности.
