# Чек-лист сдачи решения (ЛЦТ 2026)

Практическая выжимка из регламентов конкурса: форма сдачи, сроки и
критерии оценки. Источники — `source/Правила подачи решений на конкурс.md`,
`source/competition-charter.pdf` (Положение), описание кейса
`source/2. ДИТ.pdf` и ТП v2.

## 1. Поля формы сдачи

Жюри должно иметь беспрепятственный доступ к материалам (ссылки открыты «по
ссылке»). Одна и та же ссылка допустима в нескольких полях.

| Поле | Что прикладываем |
|------|------------------|
| Репозиторий | Публичный Git-репозиторий; **в корне `README.md` с инструкцией локального запуска** |
| Документация | `docs/` в репозитории (архитектура, стек, развёртывание, API) — [пояснительная записка](explanatory-note.md) |
| Презентация | Слайды по шаблону организатора — [структура](presentation-outline.md) |
| Прототип | Для backend-задачи — Swagger/тестовый эндпоинт или скринкаст работы |
| Доп. материалы | Схемы, датасет, демонстрация (не дублируют прототип/презентацию) |

## 3. Критерии оценки (Положение, 5.26)

Каждый критерий — 1…5 баллов; по задаче определяются победитель и два призёра.

1. Подход к решению задачи (уникальность и оригинальность).
2. Техническая проработка решения.
3. Соответствие решения выбранной задаче (ТЗ/ТП v2).
4. Эффективность решения в рамках задачи.
5. Выступление на питче.

## 4. Требования к материалам (Положение, 5.10–5.11)

- Презентация — о решении и команде; требования к оформлению публикуются
  организатором в личном кабинете (раздел «Хакатон»). Шаблон оформления —
  `source/ЛЦТ2026 Шаблон презентации.pptx`.
- Материалы должны быть оригинальной разработкой, не нарушать права третьих
  лиц, не содержать запрещённого законом контента.
- Данные ТЗ — конфиденциальны, не публикуются без согласия правообладателя.
