# ADR-0062. Глобальный оптимизатор Ду (финальный, по флагу)

- Статус: accepted (дефолт включён)
- Дата: 2026-09-27
- Контекст: FR-43 (Ду по расходу), FR-44 (предельная длина по путям), FR-48
  (невозрастание Ду к точке подключения), ADR-0022; конкурирующее решение
  (`DiameterOptimizer`)

## Контекст

Ду назначается жадно: минимальный по расходу на ребро, затем
`MaxLengthEnforcer` при превышении плети поднимает Ду **всей** плети. Это не
минимум стоимости: не учитывается ступень стоимости камер, а общий ствол
поднимается целиком там, где достаточно частичного подъёма. На длинных общих
магистралях с множеством веток (городской масштаб) переплата может быть
заметной.

## Решение

`routing/DiameterTreeOptimizer` — DP по дереву, выбирающий Ду на все рёбра с
минимизацией стоимости участков (`len·cнов(Ду)·Kспец`) и новых камер (ступень по
входному Ду) при ограничениях: пропускная способность, невозрастание Ду к корню,
предельная длина плети одного Ду. Так как Ду не убывает к корню, наибольший
инцидентный Ду у не-корневого узла — это Ду ребра к родителю, поэтому стоимость
камеры зависит только от входного Ду и поддеревья независимы; связь только в
камере-корне (перебор по максимуму исходящих Ду). Геометрия и длины не меняются,
поэтому минимум стоимости = минимум `S`.

Интеграция (флаг `forest-diameter-optimizer`, дефолт **on**, отключается
`HEATING_FOREST_DIAMETER_OPTIMIZER=false`):

- оптимизатор вызывается **один раз на дерево** — финальным проходом
  `GridForestPlanner.optimizeTreeDiameters` после `refine`/оптимизации/слияния
  камер; в промежуточных переборах кандидатов используется дешёвый
  `MaxLengthEnforcer`;
- проход выполняется, **только если предельная длина реально связывает**
  (`lengthBinds`: минимальные по расходу Ду дают превышение плети). Иначе
  оптимум совпал бы с `MaxLengthEnforcer`, и оптимизатор не запускается — на
  реальных наборах это исключает любые накладные расходы;
- при превышении бюджета состояний (`forest-diameter-optimizer-max-states`,
  500 000) или невыполнимости — фолбэк на `MaxLengthEnforcer` (перф-щит);
- `MaxLengthEnforcer` остаётся дефолтом и фолбэком; legacy `ForestPlanner` не
  затронут.

Доминантное прореживание состояний DP (меньшая длина плети при не большей
стоимости) признано **незвуковым** для точных запросов по длине плети:
поддерево, посчитанное при меньшей накопленной длине, может быть невыполнимо при
большей. Вместо него применён guard «связывает ли длина».

## Следствия

- Положительные:
  - на синтетике, где длина связывает (гребёнка 399 рёбер), стоимость участков
    **3.62e9 → 2.85e9 (−21 %)**; на городском масштабе с длинными стволами это
    потенциально заметный выигрыш по `S`;
  - строгое обобщение: стоимость ≤ `MaxLengthEnforcer`, есть фолбэк;
  - на проверочных наборах (осн. и OSM) предельная длина не связывает — guard
    отключает оптимизатор, `S`/`C` бит-в-бит прежние (13.4250 / 13.760947),
    накладных расходов нет.
- Отрицательные/ограничения:
  - один вызов оптимизатора в 20–70× дороже `MaxLengthEnforcer`
    (≈1 с на ~4 тыс. рёбер при связывающей длине); бюджет ограничивает время,
    но при исчерпании теряется выигрыш;
  - незвуковое доминирование не реализовано; сложность DP ограничена бюджетом;
  - эффект на текущих наборах не измеряется (0).
- Затрагивает `routing/DiameterTreeOptimizer`, `GridForestPlanner`
  (`optimizeTreeDiameters`/`lengthBinds`), `AppProperties`/`application.yml`
  (`forest-diameter-optimizer`, `-max-states`), тесты
  (`DiameterTreeOptimizerTest`, `DiameterOptimizerIntegrationTest`), `docs`.
