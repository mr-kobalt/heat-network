# ADR-0009. Конфигурируемые правила пространственных ограничений

- Статус: accepted
- Дата: 2026-09-16

## Контекст

Таблица 5.1 ТП задаёт правила для известных типов ограничений, однако
в образце данных встречаются значения, которых там нет (`oks`, `railway`),
и полный конкурсный набор может содержать не все типы. Хардкод правил
затруднит адаптацию без изменения кода (нарушение NFR-09).

## Решение

Вынести правила в конфигурацию (файл/YAML): для каждого `restriction_type`
задаются правило (запрет/спецпроход), минимальные расстояния, углы, условия
по глубине, границы спецучастка, `Kспец`. Предусмотреть дефолты и явную
диагностику для неизвестных типов (не падать, сообщать).

## Следствия

- Положительные: адаптация к другому набору без правки логики; единый источник
  правды по правилам.
- Отрицательные: нужна валидация конфигурации и синхронизация с ТП;
  риск рассинхронизации конфига и документации.
