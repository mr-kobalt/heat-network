# ADR-0012. Офлайн-режим и единственный экземпляр

- Статус: accepted
- Дата: 2026-09-16

## Контекст

Протокол встречи 16.09.2026: несколько серверов использовать нельзя; сервис
разворачивается в единственном экземпляре на первом этапе; горизонтальное
масштабирование закладывать можно, но не жёстко. Программа полностью офлайн,
без агентов с токенами. Ограничений по CPU и времени нет, но быстродействие —
дополнительный критерий.

## Решение

Проектировать приложение как одноконтурное, без обязательной внешней
инфраструктуры (кроме PostgreSQL/PostGIS). Не использовать внешние сервисы,
телеметрию и сетевые вызовы. Состояние расчёта — в БД/на диске; приложение
не требует распределённой координации. Архитектура не запрещает будущее
масштабирование (stateless-контроллеры, внешнее состояние), но не проектирует
его специально.

## Следствия

- Положительные: простой деплой, соответствие требованиям, безопасность
  (нет исходящих соединений).
- Отрицательные: пропускная способность ограничена одним инстансом; при
  росте нагрузки потребуется пересмотр (очередь, оптимизация).
