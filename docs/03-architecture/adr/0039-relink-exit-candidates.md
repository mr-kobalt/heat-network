# ADR-0039. Переприсоединение выбирает выход-кандидат точки

- Статус: accepted
- Дата: 2026-09-22

## Контекст

ADR-0037 изменил расчёт точки выхода ОКС: `target` — пересечение
перпендикуляра к внешнему контуру своей компоненты с границей буфера всего ОКС,
а в узком промежутке между соседними зданиями цель ставится в его середине.
Для точки 3 это развернуло выход на противоположную (восточную) сторону:
западный перпендикуляр упирается в буферы соседних ОКС (точек 6, 8).

`TerminalRelinker` при этом использовал **только канонический** выход
(`ConnectionExit`) каждой точки. Поэтому после ADR-0037 переприсоединение точек
8, 3, 6 к одной камере перестало срабатывать: relink строил ветку к
единственному `target` и отвергал общую камеру по `validSegment`
(буферы/углы). На наборе 3 и 8 садились на T-узел в `target` точки 8, а 6 —
на отдельную камеру; в эталонном прогоне до ADR-0037 все три сидели на одной
камере.

При этом с ADR-0037 у каждой точки уже есть список валидных выходов
(`OksApproachResolver.candidatesFor`), отсортированных по `p→target`; он
использовался только как аварийный (когда клетка канонического выхода
недостижима от сети).

## Решение

`TerminalRelinker` перебирает **все выходы-кандидаты** точки, а не только
канонический:

1. `GridForestPlanner.plan` один раз считает `Map<String, List<ConnectionExit>>`
   через `approachResolver.candidatesFor` (fallback — канонический выход),
   переиспользует карту для выбора достижимой цели роста и передаёт в
   `buildTrees`.
2. `buildTrees` формирует для relink список выходов точки: по флагу
   `forest-relink-exit-candidates` (default `true`) — все валидные
   (не `blocked`, `target != null`), не более
   `forest-relink-exit-candidates-max` (default 6); иначе — только канонический.
3. `TerminalRelinker.bestFor` для каждого выхода-кандидата строит ветку
   `[камера, target, point]` с хвостом `tail`, проверяет `validSegment`
   (запреты/углы/пересечения) и пересобирает дерево с точным `S`; применяется
   строго лучшее. Геометрические проверки и модель стоимости не меняются;
   консолидация возникает естественно, потому что точка может выбрать выход,
   смотрящий в сторону общей камеры.

## Следствия

- Положительные: консолидация точек 3, 6, 8 восстановлена — все сходятся на
  камере `br_0_12` (эталонный прогон 07:47: общая камера). Baseline улучшился:
  `S` 13.530 → 12.306, длина 1918.4 → 1730.8 м, стоимость 277.7 → 254.1 млн,
  камеры 58 → 53 млн; все 17 точек подключены; внутренних углов >90° в выводе
  нет (было 4); пересечений нет.
- Отрицательные: перебор выходов × перебор узлов/T-точек увеличивает время
  relink (тестовый прогон ~12.6 → 22 с на три сценария); ограничен
  `forest-relink-exit-candidates-max`. Baseline пересчитан в
  `CalculationPipelineSlowTest`.
- Затрагивает `GridForestPlanner` (карта кандидатов, передача в relink),
  `TerminalRelinker` (перебор выходов), `AppProperties`
  (`forest-relink-exit-candidates[-max]`), тесты (slow baseline, общая камера
  3/6/8); `OksApproachResolver` без изменений.
