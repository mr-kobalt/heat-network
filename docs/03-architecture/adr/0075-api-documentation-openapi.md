# ADR-0075. Документация API (OpenAPI/Swagger)

- Статус: accepted
- Дата: 2026-09-29

## Контекст

`springdoc-openapi-ui` 1.7.0 обязателен (PDF 3.2), Swagger UI — желателен по
протоколу и полезен как «прототип» в заявке. До этого спецификация содержала
только заголовок и версию: операции и модели без описаний, ошибочные коды и
streaming-эндпоинты не типизированы, `/api/v1/info` возвращал устаревший статус.

## Решение

1. **Описание аннотациями Swagger** (`io.swagger.v3.oas.annotations`):
   `@Tag` на контроллерах, `@Operation`/`@Parameter`/`@ApiResponses` на
   операциях, `@Schema` на DTO (`DatasetResponse`, `RunResponse`,
   `AlgorithmResponse`, `ErrorResponse`). Язык описаний — русский.
2. **Глобальная конфигурация** `OpenApiConfig`: описание сервиса и сценария
   работы, серверы, группы операций (`Service`, `Dataset`, `Runs`,
   `Algorithms`).
3. **Единая модель ошибки** — `ErrorResponse`; коды и коды ответов указаны в
   `@ApiResponses` каждой операции (400/404/409/422/500 по ситуации).
4. **Streaming-эндпоинты** (`/result`, `/stages`, `/stages/{id}`) описаны как
   файлы (`application/geo+json` или JSON, `string/binary`), т.к. тип
   `StreamingResponseBody` не интроспектируется.
5. **Версия сборки** — через `spring-boot-maven-plugin:build-info`;
   `/api/v1/info` отдаёт `service`, `version`, `buildTime`, `status=ready`.
6. **Доступ**: UI — `/swagger-ui.html`, спецификация — `/v3/api-docs`;
   визуализатор встраивает UI во вкладку «API» (ADR-0072).
7. **Тест контракта** `OpenApiDocsSlowTest` (slow, Testcontainers): проверяет
   теги, ключевые пути, схемы и доступность Swagger UI.

## Следствия

- Положительные: API самодокументирован, пригоден для ручной проверки и как
  ссылка «прототип» в заявке; единая модель ошибки; автоматический контроль
  контракта.
- Отрицательные: аннотации добавляют объём к контроллерам/DTO; описания нужно
  поддерживать при изменении API; slow-тест требует Docker/БД.
- Изменение состава API без обновления аннотаций ловится тестом контракта.
