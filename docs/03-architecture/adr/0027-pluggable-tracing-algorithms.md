# ADR-0027. Подключаемые алгоритмы трассировки (выбор через API)

- Статус: accepted
- Дата: 2026-09-19

## Контекст

Конвейер трассировки был жёстко зашит: `VariantGenerator` напрямую вызывал
`ForestPlanner` с тремя радиусами кластеризации. Появилась потребность
подключать дополнительные алгоритмы трассировки и выбирать их при запуске
расчёта, не меняя API-контракт вывода GeoJSON и не пересобирая сервис.

## Решение

1. **Контракт плагина** `ru.lct.heating.routing.algorithm.TracingAlgorithm`:
   `id()`, `description()`, `plan(dataset, graph, obstacleIndex, warnings) →
   List<ForestPlanningResult>`. Алгоритм отвечает за построение плана(ов)
   (до трёх вариантов); расчёт стоимости, спецпроходов, ранжирование и
   формирование GeoJSON — общая часть конвейера (`VariantGenerator` /
   `ForestResultBuilder`).
2. **Реестр** `TracingAlgorithmRegistry` (Spring собирает все бины
   `TracingAlgorithm`): дубликаты `id` запрещены (fail-fast); доступны
   `available()`, `require(id)` (неизвестный id → 400), `defaultAlgorithm()`.
3. **Дефолт** — конфиг `heating.app.routing-algorithm` (по умолчанию
   `grid-forest`). Устаревший `mst` удалён (ADR-0074); механизм подключения
   алгоритмов сохраняется.
4. **API**:
   - `GET /api/v1/algorithms` → `[{id, description, defaultAlgorithm}]`;
   - `POST /api/v1/datasets/{id}/runs?algorithm=<id>` — необязательный
     параметр; неизвестный id → 400 с перечнем доступных; без параметра —
     дефолт.
5. **Персистентность**: выбранный алгоритм сохраняется в
   `calculation_run.algorithm` и возвращается в `RunResponse.algorithm`.
6. **Вывод GeoJSON не меняется**: алгоритм не добавляется в
   `variant_summary` (формат по ТП фиксирован).
7. **Тесты**: быстрый сквозной тест по умолчанию на маленьком фикстуре;
   полный набор — тег `slow`, исключён из `mvn test` (surefire
   `excludedGroups`), запуск
   `mvn test -Dsurefire.excludedGroups= -Dgroups=slow`.

## Следствия

- Положительные: новый алгоритм добавляется одним бином `@Component`, без
  правок API/вывода; выбор виден в API и сохраняется в истории запусков;
  `mvn test` стал быстрым (~секунды) за счёт вынесения полного набора в slow.
- Отрицательные: за выбор алгоритма отвечает клиент; дефолт должен
  существовать, иначе сервис не стартует (fail-fast осознанно).
- Конкурсная (headless, офлайн) поставка не затрагивается: без параметра
  работает прежний `mst`.
