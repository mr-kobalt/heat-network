# ADR-0016. Асинхронная модель запуска расчёта

- Статус: accepted
- Дата: 2026-09-16

## Контекст

Входные данные могут быть большими (до 2–3 ГБ), расчёт длительным.
Синхронный HTTP-запрос упирается в таймауты и затрудняет UX. Сервис работает
в единственном экземпляре (ADR-0012).

## Решение

Расчёт выполняется асинхронно:

- `POST /runs` создаёт запись запуска в статусе `PENDING` и ставит задачу
  в in-process `ThreadPoolTaskExecutor` (число воркеров — параметр, по
  умолчанию 1–2 для контроля памяти);
- клиент опрашивает `GET /runs/{id}` (статусы `PENDING/RUNNING/DONE/PARTIAL/FAILED`);
- результат доступен потоково через `GET /runs/{id}/result`;
- без распределённой очереди, достаточно для одного экземпляра.

## Следствия

- Положительные: отсутствие таймаутов, предсказуемая нагрузка, готовность
  к длительным 2–3 ГБ расчётам.
- Отрицательные: нужны состояния, очистка старых запусков и корректная
  обработка перезапусков; при масштабировании потребуется внешняя очередь.
