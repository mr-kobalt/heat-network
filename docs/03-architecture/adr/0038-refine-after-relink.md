# ADR-0038. Порядок стадий `grid-forest`: relink → refine

- Статус: accepted
- Дата: 2026-09-22

## Контекст

В алгоритме `grid-forest` (ADR-0034/0035/0037) геометрия рёбер уточнялась
(string pulling, ремонт поворотов, grid-заход на выход) **внутри** `buildTree`,
сразу при сборке дерева из клеток сетки. Переприсоединение терминалов
`TerminalRelinker` (`relink`) выполнялось **после** и меняло топологию: рвало
ребро терминала, добавляло прямую ветку `[кандидат, target, point]` и расщепляло
ребро в T-врезке. Геометрия этих новых веток не уточнялась, а предельная длина
(`MaxLengthEnforcer`) после смены топологии не перепроверялась.

Такой порядок инвертирован: топологическая оптимизация (выбор места врезки)
работает по уже «спрямлённой» геометрии, а её собственная геометрия остаётся
сырой. Плюс разрыв инварианта предельной длины: путь после `relink` мог
превысить предел, а `enforce` для него уже не вызывался.

## Решение

Изменить порядок стадий на **топология → геометрия**:

1. `buildTree` отдаёт «сырые» рёбра из клеток сетки без `refine`,
   `rebuildExitJoint` и `enforce`.
2. `TerminalRelinker.relink` работает по сырым деревьям.
3. Новая стадия `refineTrees` (после `relink`) выполняет string pulling, ремонт
   поворотов и grid-заход на выход **для всех** рёбер финальной топологии,
   включая ветки, созданные переприсоединением. Направление входа/выхода ребра
   берётся из топологии дерева: `startPrevious` — координата родительского узла,
   `endNext` — точка ОКС при непустом `tail`; терминальный признак — тип узла
   `CONNECTION_POINT`.
4. `MaxLengthEnforcer.enforce` вызывается **после** `refineTrees` — по финальным
   уточнённым путям.
5. Оценка `S` (`estimateScore`) считается по финальному лесу.

Порядок этапов трассировки (ADR-0036) приводится в соответствие:
`trees-N` → `relink` → `refine`; так же переупорядочиваются вкладки
визуализатора и `manifest.json` (`StageTraceWriter`).

Конфигурация (ADR-0009) не меняется: поведение по-прежнему регулируется
`forest-reattach-pass`, `forest-refine-local-passes`, `forest-exit-grid-dogleg`.

## Следствия

- Положительные: топология оптимизируется до геометрии, а геометрия — по
  финальному графу; ветки `relink` тоже уточняются; предельная длина
  проверяется по фактическим путям после `relink`; вкладки визуализатора
  отражают реальный конвейер. Baseline улучшился: `S` 13.596 → 13.530,
  длина 1928.6 → 1918.4 м, стоимость 278.9 → 277.7 млн (все 17 точек
  подключены).
- Отрицательные: `relink` теперь оценивает кандидатов по сырой (более длинной)
  геометрии — решения о переприсоединении могут отличаться; baseline
  пересчитан в `CalculationPipelineSlowTest`; трактовка поворотов на стыках
  исходных рёбер использует родительский узел, а не клетку-предка (может
  слегка менять ремонт поворотов).
- Затрагивает `GridForestPlanner` (`buildTree`, новый `refineTrees`,
  перестановка `estimateScore`/стадий), `StageTraceWriter`, тесты
  (`CalculationPipelineSlowTest`, `StageTraceWriterTest`); `TerminalRelinker`
  без изменений.
