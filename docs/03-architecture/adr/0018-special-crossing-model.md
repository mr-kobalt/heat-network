# ADR-0018. Спецпроходы: модель спецзон, угол от оси и габариты

- Статус: accepted, уточнён ADR-0023 (ТП v2: спецпроход одним прямым участком,
  угол полигона в точке входа, внутри расстояние не проверяется, `railway` —
  запрет, финальный участок в `oks`)
- Дата: 2026-09-19

> **Уточнено ТП v2 (ADR-0021, ADR-0023).** Отменены: полуторакратное удорожание
> нестандартных углов (поворот произвольный до 90°, без удорожания);
> спецпроход выполняется **одним прямым участком**; угол для полигона — в точке
> входа относительно пересекаемой границы; внутри разрешённого спецпересечения
> минимальное расстояние не проверяется; `railway` — запрет (1,0 м); для `oks` —
> финальный прямой участок к точке.

## Контекст

В M1 запретные ограничения реализованы (`ObstacleIndexBuilder` строит буферы
`PROHIBITED`), а правила `SPECIAL` полностью игнорируются: они не попадают в
индекс, не влияют на маршрут, стоимость и `laying_method`. Для M2 (FR-52…FR-56,
FR-57) нужно:

- выделять пересекающую препятствие часть трассы как `laying_method = special`
  с коэффициентом `Kспец`;
- считать угол пересечения **от оси препятствия** (ось строит команда);
- для полигональных объектов мерить расстояние от внешней границы полигона, для
  линейных — между внешними границами расчётных габаритов (таблица 4.2);
- для дорог и трамвайных путей добавлять 3 м за границей/буфером;
- при наложении зон брать максимальный `Kспец`, один спецучасток без
  перемножения (ADR-0011);
- применять полуторакратное удорожание нестандартных углов отвода (FR-57);
- округлять расстояния в большую сторону (FR-58).

Открытые вопросы NQ-04, NQ-07, NQ-08 не имеют окончательного ответа
организатора, но блокируют реализацию.

## Решение

1. **Разделить индекс ограничений на два реестра.** `ObstacleIndex` хранит
   запретные буферы (как в M1); новый реестр `SpecialZoneIndex` хранит спецзоны:
   тип правила, `Kспец`, минимальный угол, ось (`Geometry`), проверочный буфер.
2. **Ось препятствия.** Для линейного ограничения осью считается входная
   `LineString`; для полигонального — внешняя граница полигона. Ось и границы
   строятся кодом (`RestrictionAxisBuilder`), не задаются в данных.
3. **Радиус проверки спецзоны.** Буфер строится на `min-distance-m` правила; для
   дорог/трамваев дополнительно расширяется на 3 м (конфигурируемо).
4. **Габариты.** Проверки линейных препятствий выполняются между внешними
   границами расчётных габаритов пары труб по таблице 4.2 (значения — в
   конфигурации `heating.envelope`). Допущение NQ-08: таблица 4.3 относится к
   существующим коммуникациям, а не к новой сети.
5. **Разбиение трассы.** Сегменты плана пересекаются со спецзонами; непрерывные
   участки, попавшие в одну или несколько зон, выделяются как один
   `special`-участок. При наложении зон `Kспец = max(...)`, без перемножения.
6. **Угол.** Угол пересечения считается между направлением сегмента и осью
   препятствия; при `angle < angle-min-deg` пересечение недопустимо (диагностика).
   Допущение NQ-07: проверяется фактический острый угол между направлениями.
7. **Нестандартные углы отвода.** Угол отвода в вершине трассы (между соседними
   сегментами) считается стандартным при `45°` или `90°`; прочие углы дают
   удорожание `×bend-surcharge` (по умолчанию 1,5) на смежные участки. Допуск
   классификации (`bend-angle-tolerance-deg`) конфигурируем. Роутер минимизирует
   число поворотов через штраф в весе рёбер (FR-57, FR-28).
8. **Округление.** Итоговые длины участков/работ округляются вверх с допуском
   `rounding-tolerance-m` (по умолчанию 0,01 м), чтобы `4,999 → 5` (FR-58).

Правила остаются конфигурируемыми (ADR-0009); значения и допущения —
`heating.app` / `heating.restrictions`.

## Следствия

- Положительные: M2 получает полный контур спецпроходов и стоимости углов;
  поведение объяснимо и адаптируемо под конкурсный набор.
- Отрицательные: NQ-04/NQ-07/NQ-08 не подтверждены; при ответе организаторов
  потребуется изменить конфиг и, возможно, логику классификации углов.
  Стоимость сегментов становится зависимой от геометрии, а не только длины.
