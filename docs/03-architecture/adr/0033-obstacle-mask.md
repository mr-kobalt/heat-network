# ADR-0033. Валидация запретов: консервативная маска и PostGIS-фоллбэк

- Статус: accepted (Фаза A — маска; PostGIS-фоллбэк — отдельная задача)
- Дата: 2026-09-21

## Контекст

На реальном прогоне `stub` (`Forest graph build = 68 287 ms` из `68 753 ms`
общего времени) узким местом оказалась **попарная геометрическая проверка**
рёбер: на каждого кандидата — `LineString`, `ownObstacles`, запрос STRtree и
JTS `relate`. Узлов было всего `1475`, рёбер `8002`, Дейкстра — `27 ms`.
Очевидная причина: проверка запретов выполняется заново для каждой пары, хотя
запреты статичны в пределах прогона.

ОЗУ целевого сервера — 16 ГБ (NFR-06); JVM-опции памяти не заданы, значит heap
по умолчанию ≈ 25% ОЗУ.

## Решение

### Фаза A (реализовано)

1. **Консервативная растровая маска** `ObstacleMask` + `ObstacleMaskBuilder`
   (ADR-0033): клетка блокируется, если её центр попадает в препятствие,
   расширенное на полудиагональ ячейки. Тогда «клетка свободна» достоверно
   означает отсутствие препятствия.
2. **Размер ячейки** — наименьшая ширина пары труб (`EnvelopeCatalog`,
   DN 50 → 0.400 м). При превышении бюджета ячейка коарсенится ×2 с warning
   `MASK_COARSENED`.
3. **Двухслойность**: грубая маска (`forest-mask-coarse-factor`, по умолчанию 8)
   для быстрого доказательства свободы; мелкая — уточнение.
4. **Бюджет памяти** `forest-mask-max-bytes` (0 — авто:
   `min(2 ГиБ, Runtime.maxMemory()/4)`).
5. **Гибридный отсев** в `UnifiedForestPlanner.buildEdges`: если маска
   гарантирует свободу — ребро принимается без точной проверки; иначе —
   точная проверка `blocked(...)` с игнором собственного `oks` терминала
   (ТП 2.2). Ложные срабатывания маски лишь добавляют точные проверки, но не
   меняют результат.
6. **Микрооптимизации**: собственные запреты терминала считаются один раз;
   `LineString` создаётся только под точную проверку; `ignoredOwn` не
   аллоцируется без терминалов среди пары.
7. **Точная проверка без DE-9IM.** `ObstacleIndex` хранит эрозию препятствий
   (`buffer(-1e-3)`) и метод `isInteriorBlocked`: вход во внутреннюю часть
   запрета — пересечение с эрозией (быстрый prepared-intersects), касание
   границы (ровно минимальное расстояние) разрешено (ADR-0025). Погрешность
   ≤1 мм. Полный `relate(...)` из горячего пути убран.

### PostGIS-фоллбэк (запланировано отдельной задачей)

При превышении бюджета ОЗУ (очень большой bbox) промежуточные данные выносятся
во временные таблицы PostGIS: буферы запретов с GiST-индексом и кандидатные
отрезки; проверка — пространственное соединение `ST_Intersects` (батч), а не
round-trip на пару. Терминальные рёбра с игнором своего `oks` валидируются в
памяти. Реализуется как порт `ObstacleValidator` с двумя реализациями
(in-memory / PostGIS) и интеграционным тестом (тег slow).

### Фаза B (реализовано): PostGIS TEMP как хранилище состояния сетки

1. **Порт** `CellStore` (состояние клеток: `dist`, `parent`, флаги) с
   реализациями `InMemoryCellStore` и `PostgisCellStore`; выбор — фабрикой
   `CellStoreFactory` по `forest-grid-storage = auto|memory|postgis` и бюджету
   `forest-grid-max-cells` (auto: в память, если клеток не больше бюджета).
2. **PostgisCellStore**: страницы 256×256 клеток (`dist+parent`), LRU-кэш
   `forest-grid-cache-mb` (default 512), сброс в **сессионную TEMP-таблицу**
   `grid_page`; соединение пиннится на прогон (TEMP живёт в сессии).
   Флаги (`settled`/`inForest`) — компактный битсет в памяти.
3. **Всегда сохраняемые промежуточные**: `GridReport` (ячейка, маска,
   источники/терминалы/деревья, метрики проходов) пишется в **`grid.json`**
   рядом со сводкой (`ForestPlanningResult` → `VariantResult` → сервис).
4. **Масштаб**: при выборе PostGIS маска не коарсенится под ОЗУ, поэтому
   доступны более мелкие ячейки на больших площадях. **Тайлы с гало** —
   отдельный следующий шаг.

## Следствия

- Положительные: `Forest graph build` перестаёт зависеть от попарных JTS-проверок;
  ожидаемо 68 с → сотни мс–секунда; результат (состав графа, score) не меняется.
- Отрицательные: дополнительная память под маску (при 0.4 м ~2 ГиБ на ~2750 км²);
  при очень большом bbox — коарсенинг (потеря точности) или PostGIS-фоллбэк.
- Консервативность маски критична: ошибка дала бы проход сквозь препятствие.
  Покрыта тестом на свойство (`ObstacleMaskTest`).
- С ADR-0034 маска применяется как **сетка проходимости** (консервативный
  одноуровневый режим, параметры `forest-grid-cell-m`/`forest-grid-max-cells`);
  попарная валидация рёбер visibility-графа больше не используется.
