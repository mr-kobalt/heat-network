# ADR-0072. Веб-доступ к документации и Swagger, диагностика расчёта, сохранение состояния

- Статус: accepted
- Дата: 2026-09-29
- Контекст: ADR-0013, ADR-0028, ADR-0036, ADR-0057, ADR-0068, ADR-0071

## Контекст

Визуализатор (ADR-0013) — опциональная оболочка над headless-сервисом. После
ADR-0059…0071 появились вопросы, которые нельзя решить на карте:

- проектная документация (`docs/`) существует только в репозитории и недоступна
  из веб-интерфейса;
- описание API (Swagger UI, `/swagger-ui.html`) приходилось открывать отдельно;
- предупреждения ingest/графа/трассировки (в т.ч. `VARIANT_GEOMETRY_FILTERED`,
  `TRACE_DISABLED_FOR_PARTITIONS`) писались в `warnings.json`, но не отдавались
  по API — пользователь не понимал, почему вариант отфильтрован или почему
  этапы недоступны;
- при режиме партиционирования (E8-15d2c2) трассировка отключается, однако
  `RunResponse.traced` оставался `true`, и клиент гарантированно получал 404 на
  манифест этапов;
- переход между разделами не должен терять текущий расчёт: результат, варианты,
  этапы и вьюпорт карты хранятся в `zustand` и не должны сбрасываться.

## Решение

1. **Разделы в шапке через хэш-роутинг.** `#map` (по умолчанию), `#docs`,
   `#docs/<path>`, `#api`. Состояние расчёта живёт в модульном `zustand`-store и
   переживает смену раздела. Карта MapLibre **не размонтируется** — скрывается
   через `display: none`; при возврате канва разово `resize()`. Фоновый опрос
   запуска (`runDataset`) не зависит от смонтированных панелей.

2. **Документация бандлится в фронтенд.** Markdown из `docs/` подключается
   `import.meta.glob('../../../docs/**/*.md', { query: '?raw' })` как ленивые
   чанки; навигация строится из курируемых индексов `docs/index.md` и
   `docs/03-architecture/adr/README.md`. Рендер — `react-markdown` + `remark-gfm`
   (GFM-таблицы, безопасный рендер без `dangerouslySetInnerHTML`); внутренние
   ссылки на `.md` открываются в разделе, внешние — в новой вкладке. Внутренние
   ссылки на `source/` в веб-версии недоступны (файлы вне контекста сборки).
   Раздел грузится через `React.lazy`, поэтому markdown-зависимости не попадают
   в основной бандл карты.

3. **Вкладка «API» — встроенный Swagger UI** backend-сервиса (`/swagger-ui` и
   `/v3` проксируются Vite в dev и nginx в Docker). Дополнительно — ссылка
   «открыть в новой вкладке».

4. **Диагностика расчёта.** Счётчики типов входных объектов из
   `DatasetResponse` выводятся в начале раздела «Сводка». Публичный показ
   предупреждений (`GET /api/v1/runs/{id}/warnings` и списки в UI) впоследствии
   убран — предупреждения остаются во внутреннем `warnings.json` и логах.

5. **Фактическая доступность трассировки.** В `CalculationOutcome` добавлен
   признак `traced`, выставляемый только при реальной записи `stages/`; по
   завершении расчёта `RunExecutor` пишет его в `CalculationRunEntity.trace`.
   `RunResponse.traced` отражает фактическую доступность файлов этапов, а не
   запрошенный флаг.

6. **Инфраструктура.** Контекст сборки фронтенда — корень репозитория:
   `docs/` копируется рядом с `frontend/` и доступен Vite-глобу; `frontend/`
   Dockerfile обновлён, корневой `.dockerignore` перестал исключать `docs/` и
   исключает артефакты фронтенда. Vite dev разрешает доступ к каталогу `docs`
   через `server.fs.allow`.

## Следствия

- Положительные: вся проектная документация и OpenAPI доступны из интерфейса;
  переключение разделов не теряет расчёт; предупреждения и отфильтрованные
  варианты объяснимы пользователю; корректный `traced` убирает ложный 404.
- Отрицательные: фронтенд получил зависимости `react-markdown`/`remark-gfm` и
  генерацию десятков мелких чанков документации; Docker-сборка фронтенда теперь
  использует контекст корня репозитория (чувствительна к `.dockerignore`);
  ссылки на `source/` в документации в вебе не работают.
- Затрагивает backend: `CalculationOutcome`, `CalculationService`,
  `RunExecutor`, `RunService`, `RunController`; frontend: `App`, `useHashRoute`,
  `docs/*`, `components/ApiView`, `DataSourcePanel`, `runDataset`, `store`,
  `types`, `api/client`, `map/MapView`, `vite.config`, `nginx.conf`, `Dockerfile`;
  инфраструктуру: `docker-compose.yml`, `.dockerignore`.
