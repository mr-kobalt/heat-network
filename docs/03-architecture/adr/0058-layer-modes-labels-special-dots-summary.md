# ADR-0058. Визуализатор: режимы слоёв и подписи, спецпроходы точками, сводная таблица

- Статус: accepted
- Дата: 2026-09-25
- Контекст: ADR-0028, ADR-0029, ADR-0055, ADR-0056, ADR-0057

## Контекст

Визуализатор (ADR-0013) показывал объекты без подписей и с булевыми
переключателями слоёв, а специальные проходы — пунктирной линией. Всплывающая
карточка объекта не помещалась в окно, а сводка вариантов дублировала данные
двумя таблицами и не давала детализации по Ду и камерам. Нужно повысить
информативность без перегрузки.

## Решение

1. **Режим слоя `off / geo / labels`.** Вместо `visibility: boolean` —
   `layerMode: Record<LayerKey, 'off' | 'geo' | 'labels'>`. На вкладке «Слои»
   каждый слой управляется трёхпозиционным `SegmentedControl`. Режим `labels`
   включает подписи:
   - камеры — «Ду {макс. входящий Ду}» (поле `diameter` камеры);
   - точки подключения ОКС — «{расход} т/ч»;
   - новая и существующая сети — «Ду · длина · стоимость» (`number-format`);
   - остальные слои подписей не имеют (режим `labels` = `geo`).

   Подписи — отдельные symbol-слои (`text-field`), шрифт `Noto Sans Regular`
   из локального набора глифов (офлайн, ADR-0012/0028).

2. **Спецпроходы — точками.** Участок со `laying_method = special` больше не
   рисуется пунктиром: его геометрия сэмплируется с шагом 4 м (пересчёт через
   `map/utm.ts`) в точечный `FeatureCollection`, который рисуется `circle`-слоем
   поверх сплошной линии сети. Базовая линия сети теперь включает спецсегменты.

3. **Компактная карточка объекта.** Попап (`DetailsPanel compact`) —
   плотная двухколоночная сетка «поле: значение» без внутренней прокрутки;
   ширина попапа до 360px. Полная таблица остаётся для некомпактного режима.

4. **Сводная таблица вариантов.** Одна таблица: колонки — варианты по рангу
   (лучший слева), строки — «Трасса», «Камеры», «Штраф», внизу — «Итого».
   Клик по «Трассе»/«Камерам» раскрывает подстроки:
   - трасса: **обычная прокладка и спецпроходы отдельно**, по каждому Ду
     `длина × цена/м = сумма` (цена/м = Σстоимость/Σдлина);
   - камеры: по каждому Ду `кол-во × цена = сумма` + отдельная строка врезок;
   - штраф: `unconnected_penalty`.
   Агрегация — на клиенте из результата (`heat_network` по `diameter` и
   `laying_method`, `heat_chamber` по `diameter`, врезки из `variant_summary`);
   контракт бэкенда не меняется. Клик по заголовку колонки выбирает вариант
   для карты.

## Следствия

- Положительные: карта читается по слоям (геометрия/подписи), спецпроходы
  наглядны, карточка объекта помещается целиком, сводка даёт детализацию и
  ранжирование в одном месте.
- Отрицательные: больше слоёв и текстовых подписей при включённых `labels`
  (возможна визуальная плотность); агрегация — O(число фич результата) на
  клиенте.
- Затрагивает фронтенд: `store`, `LayersPanel`, `DetailsPanel`,
  `VariantSummaryPanel`, `map/layers`, `map/visuals`, `map/MapView`.
