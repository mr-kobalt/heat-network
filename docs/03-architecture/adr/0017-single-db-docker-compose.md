# ADR-0017. Единая БД через docker-compose

- Статус: accepted
- Дата: 2026-09-19

## Контекст

Раньше PostgreSQL поднимался двумя способами: сервисом `services.postgres`
в devenv и контейнером `db` в docker-compose. Это порождало путаницу:
- версия PostGIS, креды и порт могли расходиться;
- devenv-PostgreSQL слушает только Unix-сокет, а JDBC-драйверу нужен TCP —
  приложение не подключалось без ручных обходов;
- возможен конфликт порта 5432 при одновременном запуске.

При этом docker-compose обязателен для сдачи (PDF 3.2): эксперты разворачивают
приложение и БД именно так.

## Решение

Использовать **единственный** экземпляр PostgreSQL + PostGIS — контейнер `db`
из `docker-compose.yml` (`docker.io/postgis/postgis`, порт `5432`,
БД/пользователь `heating`). devenv отвечает только за тулчейн (Java 11, Maven,
Node/pnpm) и не поднимает БД.

В devenv добавлены скрипты: `db-up` (`docker compose up -d db`), `db-down`,
`db-logs`, `up`/`down`. Параметры по умолчанию в `application.yml` совпадают
с compose (`localhost:5432`, `heating/heating`), переопределяются через
`SPRING_DATASOURCE_*`.

## Следствия

- Положительные: один источник истины по БД; совпадение dev и prod-окружения;
  приложение и тесты используют TCP; нет конфликтов портов и расхождений версий.
- Отрицательные: для БД нужен запущенный docker/podman (`db-up`); `devenv test`
  больше не проверяет доступность БД (проверяется отдельно в интеграционных
  тестах). Порядок запуска: сначала `db-up`, затем `run`.
