# ADR-0037. Буферы по минимальному Ду, выход ОКС по внешнему контуру, кандидаты врезки и варианты по проходам

- Статус: accepted
- Дата: 2026-09-22

## Контекст

Разбор визуализатора и повторная сверка с ТП вскрыли четыре расхождения:

1. **Запретные зоны завышены**: `ObstacleIndexBuilder` считал буферы по одному
   `default-diameter-mm` (400) на весь расчёт, включая полосы `oks` 5/7/9 м по
   этому числу, хотя фактический Ду трассы определяется позже.
2. **Поиск клетки входа терминала** (`forest-terminal-cell-search` + мультивход,
   ADR-0035) усложнял алгоритм: `target` мог попасть в заблокированную клетку,
   приходилось перебирать соседние.
3. **Кандидаты врезки** брались сэмплами каждые 30 м, что огрубляло вырезку;
   точки рядом с существующими камерами дублировались.
4. **Границы сетки** включали лишь точки сети и терминалы, поэтому обход
   препятствия, выходящий за них, оставался неисследованным.
5. Проходы стоимостного уточнения (`forest-cost-iterations`) давали разные леса,
   но в результат попадал только лучший по оценке.

## Решение

1. **Буферы — по минимальному Ду номенклатуры** (`ObstacleIndexBuilder`):
   `minDistanceForDn(dn) + halfPairWidthM(dn)`, где `dn` — минимальный Ду
   номенклатуры (50). Для `oks`-полигона с точкой подключения (`covers`) берётся
   Ду этой точки. Учёт фактического Ду на этапе `refine` — отдельная задача
   (backlog E16).

2. **Выход ОКС по внешнему контуру** (`OksApproachResolver`). Для точки:
   - находим **компоненту-полигон** своего ОКС, содержащую точку, и её **внешнее
     кольцо**; строим перпендикуляры к его рёбрам;
   - буфер — для **всего ОКС** (все компоненты): `minDistanceForDn(dn) +
     halfPairWidthM(dn)` (без диагонали клетки);
   - луч из точки через основание перпендикуляра доводим до **внешнего** контура
     буфера всего ОКС (без внутренних «дырок»); берём ближайшее пересечение;
   - **узкий промежуток:** если сразу за выходом луч снова упирается в запретный
     буфер ближе `maxPairWidthM` (наибольшая ширина пары по номенклатуре),
     выход ставится в **середине** этого промежутка — точка попадает в
     проходимый коридор между близкими зданиями;
   - из валидных кандидатов берётся минимальный `p→target`; хвост не должен
     нарушать буферы прочих ограничений.
   **Поиск клетки входа терминала и мультивход упразднены** (ADR-0035 в этой
   части superseded): терминал берёт клетку `target`. Если клетка основного
   выхода заблокирована/недостижима, **планировщик берёт ближайший альтернативный
   выход**, ведущий в достижимую клетку (`OksApproachResolver.candidatesFor`).
   Флаги `forest-terminal-multi-entry`, `forest-terminal-entry-cells`,
   `forest-terminal-cell-search` удалены.
   - **Маска проходимости** (`ObstacleMaskBuilder.buildPassability`) строится без
     расширения на полудиагональ (вариант B); клетки выходов принудительно
     открываются (`ObstacleMask.withClearedCells`). Гарантия ADR-0033 «свободная
     клетка ⇒ отрезок не пересекает запрет» для сетки ослаблена; корректность
     геометрии обеспечивает точное уточнение `refine`.

3. **Кандидаты врезки** (`TieInCandidateProvider`): все существующие камеры +
   сэмплы вдоль сети каждые `tie-in-sample-step-m` (1 м) + проекции точек выхода
   на участки; кандидат в радиусе `tie-in-chamber-exclusion-m` (1 м) от камеры
   исключается.

4. **Границы сетки** (`GridForestPlanner.bounds`) включают `bbox` всех входных
   объектов (`forest-grid-include-input-bounds`, default true) — обход может
   выходить за габариты сети.

5. **Проходы → варианты** (`GridForestPlanner.plan` возвращает
   `List<ForestPlanningResult>`): каждый выполненный проход прогоняется дальше по
   конвейеру как отдельный вариант; одинаковые по геометрии проходы
   дедуплицируются, максимум 3 (FR-75). `VariantGenerator` ранжирует по `S`.
   Идентификаторы новых камер/тех. узлов в выводе получают префикс `variant_id`,
   чтобы варианты были согласованы.

## Следствия

- Положительные: зоны ближе к ТП (меньше «завышение»); выход — ближайшая точка на
  внешнем контуре буфера своего ОКС, с учётом узких промежутков и достижимости
  (все 17 точек подключаются без «дальних прыжков» через кластер); плотное
  сэмплирование врезки; сетка покрывает весь вход; до трёх содержательно разных
  вариантов из проходов.
- Отрицательные: больше клеток сетки (полный bbox) и кандидатов (шаг 1 м) —
  рост времени/памяти, шаг и бюджет конфигурируемы; `resolveExits` стал дороже
  (буферизация соседних ограничений для узких промежутков); baseline изменился
  (`S` 12.810 → 13.596, длина 1816.8 → 1928.6 м, стоимость
  262.9 → 278.9 млн, камер 52 → 58 млн) — зафиксировано в
  `CalculationPipelineSlowTest`; допустимые `TURN_ANGLE_EXCEEDS_90` считаются по
  всем вариантам; ADR-0035 частично superseded; гарантия ADR-0033 для маски
  ослаблена (см. п. 2).
- `mst` не затрагивается (использует отдельный legacy-путь `resolve`).
