# ADR-0035. Присоединение терминалов: выбор клетки входа и граница ОКС

- Статус: accepted
- Дата: 2026-09-22

## Контекст

В алгоритме `grid-forest` (ADR-0034) терминал подключается к растущему лесу по
первой достигнутой клетке-кандидату; камеры (`br_*`) эмерджентны, а «ближайшая
камера» не является критерием. Набор 17 точек / 29 участков вскрыл проблему:
точка подключения **6** (внутри `oks`-полигона 82) присоединялась к стволу
`br_0_10` ребром 106.4 м (Ду100), тогда как камера `br_0_11` лежит в 33.9 м и
уже обслуживает точки 3 и 8. Это даёт заметную переплату по стоимости
(≈6 млн) при почти той же длине.

Причины: (1) `nearestFreeCell` выбирал стартовую клетку терминала кольцевым
сканом с уклоном (не по истинной близости), и вход оказывался не с той стороны
ОКС; (2) после подключения ребро не пересматривалось — даже если рядом позже
появлялась камера; (3) `OksApproachResolver.owningRestriction` использовал
`Geometry.contains(point)`, что ложно для точки ровно на границе полигона ОКС.

## Решение

1. **Выбор клетки входа (`forest-terminal-cell-search`)**: `raster` (прежний
   кольцевой скан), `nearest` (ближайшая по евклидову расстоянию свободная
   клетка), `toward-network` (среди ближайших — обращённая к центроиду
   источников). Дефолт — `nearest`.
2. **Многоточечный вход (`forest-terminal-multi-entry` +
   `forest-terminal-entry-cells`)**: терминал получает несколько свободных
   клеток-кандидатов разных секторов вокруг `target`; подключение — по первой
   достигнутой. Дефолт — **включено** (в сочетании с переприсоединением снижает
   `S`: см. свип v2).
3. **Граница ОКС (`oks-owning-include-boundary`)**: `owningRestriction`
   использует `covers` (учитывает границу) вместо `contains`. Дефолт — включено.
4. **Переприсоединение терминалов (`forest-reattach-pass`,
   `forest-reattach-iterations`)**: после построения деревьев для каждого
   терминального листа полным перебором ищется более дешёвая точка врезки
   (`TerminalRelinker`):
   - **кандидат** — точка `p` существующей сети дерева: координата узла
     (камера/источник/тех.узел, не точка подключения) **или** внутренняя точка
     ребра (T-врезка; ребро расщепляется, `p` — новый узел-камера);
   - T-точки: внутренние вершины полилинии, середины отрезков и проекция
     `target` на отрезок; собственное старое ребро терминала исключается;
   - новое ребро `p → target` (существующий `tail` сохраняется); проверки:
     отсутствие захода в запреты (своя ОКС точки игнорируется), поворот ≤90° на
     врезке и на стыке с `tail`, отсутствие пересечений с другими рёбрами;
   - для каждого кандидата дерево **пересобирается** (потоки, Ду, типы узлов,
     стоимости, `S`); применяется строго лучшее; проходы повторяются до
     `forest-reattach-iterations`. Дефолт — **включено** (улучшает и `S`, и
     длину ребра точки 6).

Все параметры конфигурируемы (env `HEATING_FOREST_*`,
`HEATING_OKS_OWNING_INCLUDE_BOUNDARY`); выключение возвращает прежнее поведение.

## Следствия

- Положительные: точка 6 присоединяется коротким ребром ≈33.6 м (было 106.4 м);
  `score` 13.069 → 12.810, длина 1810.5 → 1816.8 м (T-врезки), стоимость
  272.8 → 262.9 млн, камер 62 → 52 млн, предупреждений >90° — 1; выбор входа —
  по близости, а не по порядку скана; точки на границе ОКС учитываются
  (`covers`). Свип v2 (`target/algorithm-sweep-2/`, угол 90°): лучший `S`
  даёт связка `multiEntry=true` + `reattachPass=true`; `dogleg`/`boundary` на
  этот набор не влияют (лучший `S` одинаков), поэтому оставлены включёнными.
- Отрицательные: `nearest` + relink меняют топологию камер (`br_*`) и baseline;
  relink добавляет T-узлы (новые камеры) и увеличивает время (~0.4–1 с на наборе).
