# ADR-0014. Преобразование координат через Proj4J

- Статус: accepted
- Дата: 2026-09-16

## Контекст

Расчёты должны выполняться в EPSG:32637, а вход/выход — в EPSG:4326 (ТП 2).
JTS не выполняет перепроецирование (ADR-0004). Нужно лёгкое решение,
совместимое с Java 11 и офлайн.

## Решение

Использовать `org.locationtech.proj4j:proj4j` для преобразования
`EPSG:4326 <-> EPSG:32637`. Параметры UTM-зоны 37N задаются явно
(`+proj=utm +zone=37 +datum=WGS84 +units=m +no_defs`), без загрузки
внешнего набора EPSG. Преобразование применяется на входе (в 32637)
и при формировании результата (обратно в 4326).

## Следствия

- Положительные: лёгкая зависимость, детерминизм, офлайн.
- Отрицательные: при появлении наборов в других зонах/CRS потребуется
  расширение конфигурации; точность UTM корректна для целевого региона.
