# ADR-0031. Единый лес: рост от существующей сети по графу видимости

- Статус: superseded by ADR-0034 (построение графа; понятие единого леса сохранено)
- Дата: 2026-09-21

## Контекст

ADR-0019 строил лес по кластерам: single-linkage по точкам подключения, затем
MST **по евклидову расстоянию** внутри кластера и одна врезка на кластер.
Препятствия при выборе топологии не учитывались, стволы между кластерами не
объединялись, а обход появлялся только на этапе маршрутизации рёбер. ADR-0026
отложил переработку топологии (T‑присоединение к стволу, общие стволы,
маршрутно-стоимостный рост) в отдельную задачу.

Требуется строить лес с учётом препятствий и общих стволов, оценивая варианты
по итоговому показателю `S = 0,7·(C/25 000 000) + 0,3·(L/100)`.

## Решение

1. **Один план за запуск**, при этом деревьев может быть несколько: каждая
   связная компонента имеет свою врезку в существующую сеть (FR-24 — без
   замкнутых маршрутов).
2. **Граф видимости** в координатах EPSG:32637; узлы:
   - точки выхода ОКС (`ConnectionExit.target`, ADR-0032);
   - кандидаты врезки (`TieInCandidateProvider`: камеры, сэмплы сети, точные
     проекции выходов);
   - вершины буферов препятствий (`ObstacleIndex.obstaclesIn`), раздвинутые на
     малый зазор и топологически прореженные.
   **Разреженный граф**: узел соединяется с `forest-knn-k` ближайшими (по
   расстоянию) не заблокированными соседями в радиусе `forest-max-edge-m`;
   число рёбер `≈ N·k/2` вместо всех пар. Точка подключения дополнительно
   связывается с ближайшим кандидатом врезки. На рёбрах от точки выхода
   игнорируется собственный `oks`-полигон (финальный вывод, ТП 2.2).
3. **Многоисточниковый Дейкстра от сети.** Источники — кандидаты врезки, стартовая
   стоимость — стоимость камеры/врезки. Союз кратчайших путей от сети ко всем
   точкам даёт общие стволы и ветвления естественно.
4. **Итеративное уточнение** (`forest-cost-iterations`): первый проход по длине,
   далее перевзвешивание по вкладу в `S` (`0,7·стоимость + 0,3·длина`) с
   оценкой Ду по предыдущему лесу; выбирается проход с минимальным `S`.
5. **Потоки и Ду** — снизу вверх по дереву; Ду минимальный по расходу, затем
   `MaxLengthEnforcer` по каждому непрерывному пути (FR-43, FR-44, FR-48).
6. **Узлы вывода**: точка подключения — **всегда `CONNECTION_POINT` (лист)**;
   ветвление в точке подключения не допускается (FR-25), транзит через неё
   запрещён (Дейкстра не раскрывает терминальные вершины). Слияния путей и
   врезки — новые камеры; существующая камера используется при врезке.
   Проходные вершины степени 2 убираются в геометрию ребра, поэтому
   `start_node_id`/`end_node_id` ссылаются только на допустимые узлы (FR-83).
7. **Послабления на период разработки** (снимаются до конкурсной поставки):
   углы поворота не ограничиваются; врезка — любая точка сети/камера, без
   правила 10 м и лимита примыканий; разрешение само- и междеревьевых
   пересечений не выполняется.
8. Реализация — в алгоритме с id `stub` (`UnifiedForestPlanner`), без изменения
   API и формата вывода; алгоритм по умолчанию остаётся `mst`.
9. **Метрики производительности.** Конвейер и планировщик логируют (INFO) время
   стадий и объёмы: стадии `ingest`/`graph`/`obstacle`/`special`/`exits`/
   `generate`/`write`; в лесу — число терминалов, кандидатов врезки, узлов по
   типам, рёбер, время построения графа, время каждого прохода и итог
   (`Forest ...`, `OKS exits ...`). Это основа для дальнейшей оптимизации.

## Следствия

- Положительные: топология учитывает препятствия и стоимость; общие стволы
  появляются без кластеризации; изолированный частичный результат сохраняется
  (`unconnected_oks_ids`).
- Отрицательные: глобальный граф дороже на больших наборах (ограничивается
  `forest-max-edge-m`/`forest-max-nodes`); итеративная оценка приблизительная;
  без разрешения пересечений возможны пересечения участков (FR-29).
- ADR-0019 (кластеризация) остаётся в силе для `mst`; для нового алгоритма
  кластеризация не применяется.
