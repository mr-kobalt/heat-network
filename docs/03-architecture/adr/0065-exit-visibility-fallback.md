# ADR-0065. Visibility-фолбэк терминального ствола (E50-07)

- Статус: accepted (включено по умолчанию)
- Дата: 2026-09-28

## Контекст

Поиск пути идёт по сетке с ячейкой `forest-grid-cell-m` (1 м) —
недилатирующей маске проходимости (ADR-0037/0041). Свободную полосу **уже
ячейки** сетка не представляет: центры клеток в неё не попадают, и маршрут
вынужден огибать. Терминальный ствол при этом может идти у самого буфера
**своего** ОКС; буфер неприкосновенен (ТП, ADR-0052), поэтому трасса обязана
идти с зазором. Крайний случай E50-07: прямой отрезок `ствол→target` заходит на
~0.22 м внутрь своего буфера (нелегален), а законная полоса снаружи буфера уже
1 м — сетка её не прошивает и врезается дальше по длине.

## Решение

Добавлен точечный **visibility-фолбэк** терминального ствола (флаг
`forest-exit-visibility-fallback`, по умолчанию **on**):

1. Только для терминального ребра с непустым хвостом (`target→point`) и только
   если прямой отрезок `from→target` заходит во внутреннюю часть запретной зоны
   (`ObstacleIndex.isInteriorBlocked`), а перепробег текущего ствола лежит в окне
   `[forest-exit-visibility-min-detour-m, -max-detour-m]` (2…10 м): малый
   перепробег — следствие дискретизации сетки, крупный — иная причина, где
   фолбэк бесполезен (и дорог).
2. Строится локальный граф видимости: узлы — `from`, `target` и вершины
   запретных буферов в окрестности прямого отрезка (расширение
   `max(25 м, 0.2·L)`, предел `forest-exit-visibility-max-nodes`, 200).
3. Рёбра, заходящие во внутреннюю часть запрета, отбрасываются; **касание
   границы буфера допустимо** (эрозия 1e-3, ADR-0025/0033) — это и позволяет
   идти вдоль границы своего буфера с зазором ровно 0.
4. Угол поворота ≤ `forest-max-turn-deg` (90°), включая стык со стартовым
   подходом и хвостом `target→point`. Канонический `target` и точка подключения
   сохраняются; заменяется только ствол до `target`.
5. Замена принимается, только если ствол строго короче (>0.5 м) и все углы
   допустимы. `Kспец`, пересечения с соседними рёбрами и предельная длина
   обрабатываются последующими стадиями `refine`/`repairCrossings`/
   `MaxLengthEnforcer`.
6. **Защита времени (NFR-08).** Кандидаты отбираются дешёвым тестом в
   детерминированном порядке (`trees` → рёбра), и попытки делаются только для
   первых `forest-exit-visibility-max-attempts` (200). Это ограничивает
   суммарные накладные расходы и не зависит от параллелизма деревьев
   (детерминизм, NFR-10). При `forest-exit-visibility-fallback=false` фолбэк
   полностью отключён.

## Результаты

- Синтетический тест `ExitVisibilityFallbackTest` (полоса 0.5 м между буфером
  ОКС и буфером здания): сеточный ствол 170 м → фолбэк 114 м, все сегменты вне
  внутренней части запретов, углы ≤90°; отдельно проверено окно перепробега и
  отключение флага.
- Основной набор (`forest-exit-visibility-fallback=true`): `S` 13.4250003 →
  13.4203952 (длина 1913.09 → 1912.29 м, −0.8 м); самопересечения/повороты/
  спец/exit mismatch/степень — **0**; применено на 2 терминальных рёбрах.
  Время без окна/предела: `Grid total` 5180 → 6258 мс (5 попыток); с окном и
  пределом остаётся 2 попытки, накладные расходы в пределах шума (`Grid total`
  ≈ 4.4–5.2 с). Baseline `CalculationPipelineSlowTest` пересчитан
  (`S` 13.420395171405428, длина 1912.2899838018095, `C` 274411615).
- OSM: срабатываний **0**, `S` без изменений (случай E50-07 в текущей редакции
  набора не воспроизводится — терминальное ребро точки 17 является прямой из
  3 вершин); пиннинги `GridForestOsmInvariantsSlowTest` не менялись.
- Быстрые тесты: `mvn -B test` — 141 без падений; `AppPropertiesEnvBindingTest`
  покрывает новые env-ключи. Полный slow-набор зелёный (sweep-тесты требуют
  поднятой БД).

Флаг включён по умолчанию; отключается
`HEATING_FOREST_EXIT_VISIBILITY_FALLBACK=false` без пересборки.

## Следствия

- Положительные: узкий коридор у своего ОКС перестаёт быть тупиком сетки; путь
  укладывается с зазором к буферу (FR-51/59 соблюдаются точнее); окно перепробега
  и детерминированный предел попыток ограничивают время (NFR-08) и сохраняют
  детерминизм (NFR-10).
- Отрицательные: O(n²)-Дейкстра по локальному графу видимости на терминальное
  ребро-кандидат (ограничена `maxNodes`, окном перепробега и
  `max-attempts`); потенциальные новые пересечения с соседними рёбрами —
  снимаются стадией разрешения пересечений; на разреженных наборах эффект
  отсутствует; выигрыш по `S` мал и локален.
- Baseline `CalculationPipelineSlowTest` пересчитан (`S` 13.4250003 → 13.4203952).
