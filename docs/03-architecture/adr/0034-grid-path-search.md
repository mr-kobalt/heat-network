# ADR-0034. Поиск пути по сетке (единый лес)

- Статус: accepted
- Дата: 2026-09-21

## Контекст

Построение visibility-графа (ADR-0031) упиралось в попарные геометрические
проверки: на наборе 17 точек / 29 участков `Forest graph build` занимал ~68–72 с,
из них почти всё — точные проверки рёбер. Оптимизация проверки без `relate`
(ADR-0033) ускорила в ~6 раз (11.5 с), но принципиально не убрала попарную
природу: 1374 Steiner-вершины лежат на границах препятствий, и каждое ребро
всё равно проверяется отдельно. NQ-01 («шаг дискретной сетки») ранее был закрыт
как `wontfix` — геометрия непрерывна.

## Решение

Поиск пути — по **сетке**; непрерывность входной геометрии и точки врезки
сохраняется (проекции, ADR-0026).

1. **Сетка проходимости** строится один раз через `ObstacleMaskBuilder`
   (консервативный одноуровневый режим): клетка блокируется, если пересекает
   буфер запрета. Тогда отрезок между центрами свободных клеток (4/8-связность)
   гарантированно не пересекает запретную зону. Ячейка — `forest-grid-cell-m`,
   бюджет клеток — `forest-grid-max-cells`.
2. **Инкрементальный рост леса** от клеток существующей сети (кандидаты врезки:
   камеры, сэмплы, проекции) по 8-связности (диагональ — при свободных
   ортогональных соседях). Dijkstra в одной очереди: при достижении терминала
   его путь фиксируется, промежуточные клетки пути становятся частью леса
   (T-присоединение к ближайшей точке уже проложенной трубы), терминальная
   клетка в лес не добавляется — точка подключения всегда лист (FR-25).
   Терминалы подключаются в порядке возрастания расстояния до текущего леса.
3. **Топология** извлекается из дерева клеток: корень — врезка, терминалы —
   листья, клетки с ≥2 детьми (включая T-присоединения) — камеры-развилки;
   проходные клетки сворачиваются в геометрию.
4. **Геометрия рёбер**: ствол уточняется string pulling по точной проверке
   `ObstacleIndex.isInteriorBlocked` (касание границы допустимо, ADR-0033) по
   **всем** запретам; собственная ОКС игнорируется только на сегментах с
   точкой выхода (`клетка→target`, `target→point`); `target` — обязательная
   неудаляемая вершина, геометрия не сокращается через здание (ТП 2.2).
5. **Сборка вывода** — существующая: потоки, Ду по расходу, предельная длина
   (`MaxLengthEnforcer`), узлы/камеры, `ForestResultBuilder`/`VariantGenerator`.
6. Точка вне ОКС — без хвоста (как в ADR-0032). Поиск устойчив: недостижимые
   точки попадают в `unconnected_oks_ids`.
7. **Метрики**: `Grid: cell/size/blocked/build`, `Grid pass i/N:
   score/trees/time`, `Grid total: sources/terminals/trees/unconnected/time`,
   `Summary: score/length/cost/unconnected`; предупреждения логируются и
   пишутся в `warnings.json` рядом со сводкой.
8. **Стоимость в рост**: `forest-cost-iterations` (default 2). Проход 0 — по
   длине; далее вес шага — вклад в `S` (`0,7·cнов(Ду)·шаг/25e6 + 0,3·шаг/100`),
   где Ду берётся из оценки по клеткам предыдущего леса; стартовая стоимость
   врезки (существующая камера дешевле новой) учитывается в источниках, поэтому
   дешёвая врезка может выиграть у более короткой; выбирается проход с
   минимальной оценкой `S`.
9. **Калибровка**: параметры сетки переопределяются через окружение
   (`HEATING_FOREST_GRID_CELL_M`, `HEATING_FOREST_GRID_MAX_CELLS`,
   `HEATING_FOREST_COST_ITERATIONS`) — для свипа ячейки без правки конфигурации.
10. **Устойчивость терминала**: кандидат-клетка точки подключения выбирается
    только из связной компоненты свободных клеток, содержащей кандидатов врезки
    (изолированные «карманы» исключаются). Итерации стоимости прерываются
    досрочно, если оценка `S` не улучшилась.
11. **Поворот ≤90° (FR-34)**: `forest-max-turn-deg` (default 90,
    `forest-turn-enforcement = hard|warn`). Входящее направление клетки берётся
    из её родителя; в релаксации роста ребро отбрасывается при угле > порога —
    это действует и на T-стыках (родитель клетки леса фиксирован). Уточнение
    геометрии — turn-aware string pulling. Недопустимый поворот ремонтируется
    **локально** (`forest-refine-local-passes`, default 2): спрямление всего
    ребра сохраняется, а окрестность нарушения возвращается на сеточную ломаную
    (раньше любой сбой откатывал ребро целиком — это давало зигзаги). Стык
    вывода правится отдельно (`forest-exit-grid-dogleg`, default true) —
    промежуточной вершиной по 8 соседям сетки, если это не упирается в запрет.
    `target` (выход ОКС) — обязательная вершина.

### Калибровка ячейки (набор 17 точек / 29 участков)

Первичная калибровка (до роста с T-присоединениями):

| Ячейка | S | Длина, м | Время grid, мс | unconnected |
|--------|---|----------|----------------|-------------|
| 0.5 м | 18.71 | 2925 | ~3100 | 0 |
| 1.0 м | 19.08 | 2939 | ~620 | 0 |
| 2.0 м | 18.79 | 2899 | ~155 | 0 |
| 3.0 м | 19.41 | 2988 | ~330 | 0 |

После перехода к инкрементальному росту с T-присоединениями выполнен свип
48 комбинаций (`AlgorithmParameterSweepTest`): `forest-grid-cell-m` ×
`forest-cost-iterations` × `forest-max-turn-deg` × `forest-grid-storage`.
Итоги: лучший `S` ≈ 13.64 (cell 2.0, iter 2, turn 180, memory), самый быстрый
прогон 145 мс (cell 3.0, iter 1, turn 180).

**Рабочие дефолты**: `forest-grid-cell-m = 2.0`, `forest-cost-iterations = 2`,
`forest-max-turn-deg = 90`, `forest-grid-storage = auto`,
`forest-refine-local-passes = 2`, `forest-exit-grid-dogleg = true`.
С локальным ремонтом поворотов baseline: `S ≈ 13.690`, длина 1893.3 м, деревьев
4, `unconnected = 0`, предупреждений `TURN_ANGLE_EXCEEDS_90` — 2 (стыки вывода).
Зигзаги устранены: `e_0_12` 29→7 вершин, `e_0_23` 10→5; вариант без grid-захода
даёт `S ≈ 13.665`, длину 1888.9 м, но 5 нарушений >90° (включая 91/98° внутри
подхода). `auto` на малом наборе эквивалентен памяти, но сохраняет PostGIS-спилл
(ADR-0033, фаза B) на больших площадях.

## Следствия

- Положительные: нет попарных проверок и Steiner-узлов; сложность ~O(клеток);
  процесс детерминирован; общие стволы естественны.
- Отрицательные: дискретизация топологии (уточняется сглаживанием);
  консервативная маска на крупной ячейке может «закрыть» узкие коридоры;
  память под массивы сетки (бюджет `forest-grid-max-cells`). Для очень больших
  площадей — PostGIS-фоллбэк (ADR-0033, отдельная задача).
- ADR-0031 (visibility-граф) в части построения графа **superseded** этим ADR;
  понятие единого леса сохраняется.
- Ограничение ≤90° действует на новую сеть (рост и уточнение). Финальный вывод
  к точке ОКС задан резолвером (ТП 2.2, перпендикуляр к границе) и при
  8-направленной сетке угол стыка «ствол→`target`→точка» может незначительно
  превышать 90°. Локальный ремонт не даёт этому нарушению откатить всё ребро
  (зигзаг), а grid-заход убирает большую часть таких стыков; на наборе остаётся
  2 предупреждения `TURN_ANGLE_EXCEEDS_90` (e_0_3 106°, e_0_15 95°), где
  grid-заход заблокирован зоной ОКС.
- NQ-01 переводится в `superseded by ADR-0034` (сетка — пространство поиска,
  не дискретизация входной геометрии).
