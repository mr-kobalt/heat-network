# ADR-0049. Производительность grid-forest: гейтинг спецзон, примитивный поиск, параллелизм деревьев

- Статус: accepted
- Дата: 2026-09-24
- Контекст: E8 (качество и производительность), NFR-08, ADR-0034/0045

## Контекст

После E25–E47 (строгий обход спецпроходов, Kспец в целевой функции,
ремонт поворотов/пересечений, оптимизация корня) `grid-forest` стал
существенно медленнее. По артефактам прогонов (`data/runs/*/grid.json`):
на наборе с препятствиями OSM один проход вырос с ~4.7 с (13:40) до
26–37 с (14:19+), `Grid total` — до 40 с; на `Датасет скорректированный`
проход — ~9 с. Замер с гранулярными таймерами показал два независимых
узких места:

1. **`SpecialZoneIndex.angleOk` в цикле роста** (E41): вызывался на
   **каждом** ребре релаксации. На OSM (226 спецзон, из них дороги с
   ограничением угла) это давало ~26.6 с из 35.7 с проходов. A/B с
   отключением проверки: Dijkstra 10.3/16.3 с → 0.25/2.8 с.
2. **`Kспец`-растр** (`specialKRaster`) считал границы `r0..r1` по шагу
   `cellM`, тогда как у гексагональной сетки вертикальный шаг строк
   `cellM·(√3/2)`. Часть клеток зоны не растеризовалась (скрытый баг).

## Решение

Чисто производительные меры (геометрия/`S` по возможности сохраняются;
изменения, влияющие на результат, помечены):

1. **Гейтинг `angleOk` по растру.** В `zoneRasters` (объединяет
   `Kспец` и маску углов) строится битсет клеток в полосе
   `2·cell` вокруг **оси** угловой зоны (буфер `2·cell` гарантирует
   перехват любого ребра роста длиной ≤ `cell·√2`). Точный
   `SpecialZoneIndex.angleOk` вызывается только если хотя бы один конец
   ребра в маске. `SpecialZoneIndex` получил отдельный `angleTree`
   (только зоны с `angleMinDeg`). Поведение эквивалентно сплошной
   проверке (проверено счётчиком «промахов» = 0).
2. **Исправлен шаг строк растра спецзон** — по `ObstacleMask.rowSpacing()`
   (для hex `cellM·√3/2`) вместо `cellM`; это исправляет и `Kспец`, и
   маску углов. **Влияет на результат:** на OSM `S` 13.348988 → 13.512036
   (учёт `Kспец` стал корректным; инварианты: 0 самопересечений,
   0 поворотов).
3. **`gridPath` на примитивах.** Рабочее пространство
   `GridPathWorkspace` (ThreadLocal): хеш-таблица состояний
   `cell*9+dir` на массивах (`keys/dist/parent` + список занятых слотов),
   бинарная heap на параллельных массивах без объектов `Node`/боксинга;
   соседи сетки — общие `int[][]` (индекс `idx` входит в ключ).
   Порядок операций heap и вес ребра (`Math.sqrt`, как
   `Coordinate.distance`) сохранены для детерминизма.
4. **Префильтр по маске в `gridPath`.** `ObstacleMask.anyBlockedAlong`
   без аллокаций (`double`-перегрузка): точная JTS-проверка сегмента
   выполняется только если маска не гарантирует свободу. Для индексов с
   добавленными препятствиями (`withAdditional`) передаётся
   `trustMask=false` — extras в маске отсутствуют. **Влияет на результат
   незначительно** (открытые коридоры выходов): OSM `S` 13.512036 →
   13.508663, инварианты сохранены.
5. **Кеш геометрии рёбер в `TerminalRelinker`.** Линии и envelope рёбер
   строятся один раз на перебор кандидатов; перед JTS `crosses` —
   отсев по габаритам (поведение эквивалентно).
6. **Параллелизм по деревьям** (`forest-*` не меняются): `TerminalRelinker.relink`,
   `GridForestPlanner.refineTrees`/`optimizeRoots` обрабатывают деревья
   независимо через `IntStream.range(...).parallel()`. Порядок
   результатов и предупреждений детерминирован (по индексу дерева),
   `idBase = index * 10_000_000`, `gridPath` использует ThreadLocal-буфер.
   Baseline не изменился.

## Следствия

- Положительные: на OSM `Grid total` 40.3 → ~18.6 с (Dijkstra 26.6 → ~2.2 с);
  `SpecialRoutingExperimentTest` (3 теста) 168 → ~101 с; `mvn test`
  остаётся быстрым. На `Датасет скорректированный` baseline `S`
  **13.580152442677246 сохранён** (без спецзон изменения не влияют).
- Отрицательные/ограничения:
  - параллелизм использует общий `ForkJoinPool` (единственный экземпляр,
    NFR-07); выигрыш ограничен доминированием одного дерева по числу
    терминалов;
  - `trustMask` ослабляет проверку в открытых коридорах — принято как
    допустимое (коридоры открываются намеренно), покрыто инвариантами;
  - при остаточной медленности резерв — ограничение кандидатов relink и
    кеш `rebuild`, вынесены в backlog E8.

## Затронутые файлы

`SpecialZoneIndex` (angleTree), `GridForestPlanner` (zoneRasters,
GridPathWorkspace, префильтр, параллелизм), `ObstacleMask`
(`anyBlockedAlong(double…)`), `GridShape`/`HexGridShape`/`SquareGridShape`
(соседи `int[][]`), `TerminalRelinker` (кеш геометрии, параллелизм).
