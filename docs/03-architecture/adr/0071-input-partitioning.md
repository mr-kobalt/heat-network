# ADR-0071. Пространственное партиционирование входа (E8-15d2c)

- Статус: accepted, **выключено по умолчанию** (`forest-partition-tile-m=0`)
- Дата: 2026-09-29

## Контекст

NFR-08 требует потоковой обработки входа 2–3 ГБ. Даже после E8-15b…d2b узкое
место — удержание всех объектов (с JTS-геометрией) и глобального
`ObstacleIndex` в памяти: `NetworkDataset` и запретный индекс строятся один раз
на весь вход. `ForestResultBuilder` также требует `ObstacleIndex`.

## Решение

Пространственное партиционирование всего конвейера:

1. **Партиционер** `DatasetPartitioner`: вход читается дважды. Проход 1 — bbox
   набора; тайлы по `forest-partition-tile-m`; проход 2 — раскладка фич по
   JSONL-файлам тайлов (LRU-пул писателей). Линии/полигоны дублируются во все
   тайлы, чей bbox расширен на `forest-partition-margin-m` пересекает габарит;
   точки подключения — ровно в один тайл; источники — во все. Манифест
   `partition.json`.
2. **Оркестрация по тайлам** (d2c2, следует): для каждого тайла — локальный
   конвейер (ingest → graph → obstacle/special → exits → plan с декомпозицией
   off) и сбор вариантов; глобальное слияние и потоковый вывод.

## Последствия

- Пиковая память ограничена размером тайла, а не всего входа.
- Маршруты/общие стволы между тайлами теряются (для очень крупных наборов
  допустимо); margin уменьшает швы.
- Детерминизм: тайлы row-major, порядок фич сохраняется.
- По умолчанию выключено: проверочные наборы и baseline не меняются.
- Партиционер + тест `DatasetPartitionerTest` (d2c1); оркестрация — d2c2.
