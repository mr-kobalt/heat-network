# ADR-0046. Присоединение и примыкания в `grid-forest` (10 м, степень ≤4)

- Статус: accepted (E26; включено по умолчанию)
- Дата: 2026-09-23

## Контекст

Правила присоединения реализованы полностью только в legacy-алгоритме `mst`
(`ForestPlanner.resolveChamber`/`hasCapacity`/`enforceDegree`). Дефолтный
`grid-forest` их ослабляет (задокументированное временное ослабление):

- радиус 10 м (`chamber-tie-in-radius-m`) в `grid-forest` не используется;
  существует только исключение кандидатов в 1 м (`tieInChamberExclusionM`);
- лимит ≤4 примыканий проверяется лишь для кандидатов relink
  (`TerminalRelinker.degreeWithinLimit`), не учитывает существующие примыкания
  камеры (проходная линия = 2, FR-26) и не валидирует итоговое дерево;
- подсчёт врезок расходится: `TerminalRelinker` — по полной степени,
  `ForestResultBuilder` — по исходящим рёбрам.

Ослабление должно быть снято до конкурсной поставки.

## Решение (предлагаемое)

1. **Радиус 10 м.** При выборе корня дерева: если в `chamber-tie-in-radius-m`
   есть существующая камера с `existingAttachments + plannedUsage < 4` —
   использовать её; иначе создать новую камеру в выбранной точке сети.
2. **Степень ≤4.** Учитывать `ExistingNetworkGraph.chamberAttachments`
   (проходная линия = 2) вместе с планируемыми рёбрами; валидировать и при
   необходимости перестраивать **итоговое** дерево после relink, а не только
   кандидатов.
3. **Единый подсчёт врезок:** врезка = каждый новый линейный участок,
   заканчивающийся в существующей камере; одна и та же формула в relink,
   `estimateScore` и `ForestResultBuilder`.

## Реализовано (2026-09-23)

- **E26-01.** `GridForestPlanner.preferExistingChambers`: сетевые кандидаты
  врезки в пределах `chamber-tie-in-radius-m` (10 м) от существующей камеры с
  запасом примыканий исключаются — рост врезается в камеру (FR-22).
- **E26-02.** `TerminalRelinker.degreeWithinLimit` учитывает существующие
  примыкания камеры (`graph.chamberAttachments`, проходная линия = 2) при
  выборе кандидатов relink; добавлена диагностика
  `FOREST_CHAMBER_DEGREE_EXCEEDED` по итоговому дереву.
- **E26-03.** Единый подсчёт врезок: `ForestResultBuilder` считает все
  инцидентные рёбра существующей камеры (не только исходящие) — как
  `TerminalRelinker`. Нейтрально на текущих данных (корень ориентирован наружу).

A/B на основном наборе (`ChamberTieInExperimentTest`): правила включены —
`S` 13.5199, длина 1903.1 м, неподключённых 0, диагностик степени 0,
неразрешённых поворотов (FR-34) **0**.

Локальные зигзаги (FR-28), возникавшие при включении правила 10 м, устранены
общим упрощением рёбер (`GridForestPlanner.simplifyEdges`: жадное удаление
лишних вершин без нарушения углов и запретов). Поэтому правила включены по
умолчанию (`forest-chamber-tie-in-rules: true`).

## E35. Оптимизация точки врезки корня (2026-09-23)

- `GridForestPlanner.optimizeRoots` (флаг `forest-root-optimization`, вкл. по
  умолчанию): для дерева с новой камерой точка врезки сдвигается на ближайшую
  перпендикулярную проекцию на сеть, если корневое ребро становится короче без
  нарушения запретов, углов на ветвлении и самопересечений. Терминальные рёбра
  (к точке подключения) не затрагиваются.
- Основной набор без изменений; E29 `S` 13.3214 → 13.3170, инварианты 0/0/0.

## Следствия

- Стоимость и топология согласуются с ТП 2.4/3.2 по умолчанию.
- E26-03 (подсчёт врезок) активен всегда.
- `simplifyEdges` даёт дополнительное улучшение FR-28 и на дефолтном режиме.
