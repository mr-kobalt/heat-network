# ADR-0032. Каноническая точка выхода из полигона ОКС

- Статус: accepted (применяется новым алгоритмом; mst временно на правиле
  ADR-0024)
- Дата: 2026-09-21

## Контекст

ADR-0024/0025 описывали вывод к точке подключения в `oks`-полигоне как набор
кандидатов: ближайший допустимый перпендикуляр, запас `oks-exit-clearance-m`,
откат на прямой выход из кармана и перебор достижимых кандидатов. Правила
давали разные точки выхода в зависимости от достижимости сети и не гарантировали
однозначную точку, а отступ считался под фиксированный `default-diameter-mm`
(400), а не под фактический Ду участка.

Требуется однозначное правило: одна каноническая точка выхода на точку
подключения, единая для всех алгоритмов, с Ду по расходу самой точки.

## Решение

1. **Общий резолвер.** `OksApproachResolver.resolveExits(dataset)` считает по
   одной `ConnectionExit` на точку подключения; результат передаётся в контракт
   `TracingAlgorithm.plan(...)` (`Map<String, ConnectionExit>`).
2. **Ду на точку.** `designDiameterMm = DiameterCatalog.select(flow_tph).getDn()`.
   При переполнении номенклатуры точка помечается `blocked`.
3. **Фигура ОКС.** Берётся выпуклая оболочка `oks`-полигона (`convexHull()`).
4. **Точка выхода.** От точки подключения — перпендикуляр к ближайшему ребру
   оболочки; в его продолжении на расстоянии
   `minDistance(oks, Ду) + halfPairWidth(Ду)` — точка `target`.
5. **Допустимость.** `target` и отрезок `[target, точка]` не должны попадать в
   буферы **чужих** ограничений; иначе `blocked`.
6. **Хвост.** `tail = [target, точка]` — финальный прямой участок; он включается
   в геометрию ребра как есть, маршрутизация ведётся от `target`, точка передаётся
   как ограничение поворота на стыке.
7. **Точка вне ОКС** — `target` совпадает с точкой подключения, `tail` пуст.
8. **Отказы.** Перебор нескольких перпендикуляров, «выход из кармана»,
   `oks-exit-clearance-m` и проверка достижимости кандидатов не используются.

## Следствия

- Положительные: единое детерминированное правило выхода; отступ зависит от
  фактического Ду; контракт алгоритмов полный — новые алгоритмы не дублируют
  вывод к ОКС.
- Отрицательные: для невыпуклых ОКС (колодцы, П-формы) ближайший перпендикуляр
  к оболочке может попасть в чужой буфер — точка не подключается (ранее был
  откат на другую грань/карман).
- `mst` пока считает выход внутри `ForestPlanner` по прежнему правилу
  (ADR-0024); перевод mst на общий резолвер — отдельный шаг. До этого правила
  выхода у `mst` и нового алгоритма различаются.
- `OksApproachPolicy`/`oks-exit-clearance-m` сохраняются только для ветки `mst`.
