# ADR-0057. Прогресс расчёта, уведомления и UX визуализатора

- Статус: accepted
- Дата: 2026-09-25
- Контекст: ADR-0016, ADR-0036, ADR-0055, ADR-0056

## Контекст

Расчёт асинхронный (ADR-0016): клиент опрашивает `GET /runs/{id}` и видит только
статус `PENDING/RUNNING/DONE/PARTIAL/FAILED`. На длительных наборах (поиск трасс
по сетке) пользователь не понимает, на каком шаге расчёт и сколько ждать; статус
жил в локальном состоянии панели «Данные» и пропадал при переключении вкладок
(ADR-0055). Появились и замечания по UX визуализатора: горизонтальные вкладки,
отступы, компактные подписи вариантов, поведение попапа у границ карты, зум при
смене дерева, размер шрифтов и контролов.

## Решение

1. **Контракт прогресса.** `CalculationService.calculate(...)` получает
   `ProgressReporter` (этап + 0…100), монотонный. Вехи: `ingest`, `graph`,
   `obstacles`, `special`, `exits`, `generate`, `write`, `trace`, `done`. Внутри
   `generate` `StageTrace.reportPass(pass, total)` (работает и без трассировки)
   даёт прогресс по проходам поиска. Старые перегрузки используют no-op —
   результат и baseline не меняются.

2. **Хранение и API.** `calculation_run` получает `stage` и `progress`
   (идемпотентные `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`); `RunExecutor`
   пишет их репортером; `RunResponse`/`ApiMapper` отдают поля клиенту.

3. **Уведомления.** Визуализатор показывает ход расчёта как Mantine-уведомление
   (`@mantine/notifications`): «В очереди» → «Выполняется: <этап> N%» →
   «Успешно»/«Ошибка»; обновление по `id` запуска, ошибка не закрывается
   автоматически. Статус — в глобальном store, поэтому виден на любой вкладке.

4. **Индикация вместо кнопки.** Пока расчёт идёт, кнопка «Загрузить и
   рассчитать» заменяется прогресс-баром с подписью этапа и процентом.

5. **UX-правки визуализатора.**
   - вкладки левой панели — горизонтально вверху, с отступами контента;
   - подписи вариантов — только `#1`, `#2`; чипы проходов — на линии с
     названием этапа; пояснение синхронизации — в `Alert`-блоке;
   - попап не уходит за видимую область карты (пересчёт якоря после отрисовки
     контента, `ResizeObserver`), не масштабирует карту при смене дерева;
   - подсказки слоёв — без внутренней прокрутки, крупнее шрифт;
   - контролы карты — крупнее и по центру левого края (не пересекаются с
     уведомлениями справа).

## Следствия

- Положительные: понятный прогресс на длинных расчётах, единый статус на всех
  вкладках, аккуратная раскладка.
- Отрицательные: новые колонки БД и поля контракта; лишние записи `run` при
  смене этапа/прохода (единицы, в рамках async-модели ADR-0016); фронтенд
  зависит от `@mantine/notifications`.
- Затрагивает `CalculationService`, `StageTrace`, `GridForestPlanner`,
  `RunExecutor`, `CalculationRunEntity`, `schema.sql`, `RunResponse`,
  `ApiMapper`; фронтенд — `store`, `client`, `runStages`, `DataSourcePanel`,
  `App`, `StagePanel`, `VariantSummaryPanel`, `LayersPanel`, `MapView`,
  `controls`, `theme`.
