# ADR-0068. Пространственная декомпозиция точек подключения (E8-15c)

- Статус: accepted, **выключено по умолчанию** (`forest-decomposition=false`)
- Дата: 2026-09-29

## Контекст

NFR-08 требует потоковой обработки входа 2–3 ГБ. `grid-forest` строит одну
растровую сетку по общему bbox всего входа (`bounds()` ∪ `dataset.getBounds()`).
Даже после E8-15b (разреженные `Kспец`/`dnEstimate`, фронтальный BFS) на
city-scale остаются плотные структуры на всю область: `ObstacleMask.fine`,
битсет `reachable`, `CellStore`, карты дерева (`parentMap`/`children`/`flow`),
а `ObstacleIndexBuilder`/`TieInCandidateProvider` держат весь вход в памяти.

## Решение

Пространственная декомпозиция (`GridForestPlanner.plan`):

1. **Кластеризация** точек подключения union-find по радиусу
   `forest-cluster-radius-m` (детерминированно, компоненты по минимальному
   индексу).
2. **Локальная подзадача** на кластер (`planSingle`): bbox = цели кластера +
   `forest-cluster-margin-m`, без глобального `dataset.getBounds()`; врезки
   фильтруются по bbox; сетка/маска/`CellStore`/растры — локальные.
3. **Учёт занятости камер** (`chamberUsage`): после кластера новые примыкания к
   существующим камерам учитываются, последующие кластеры не занимают камеры
   сверх `forest-max-chamber-degree` (FR-26).
4. **Слияние** по номеру прохода: каждый глобальный вариант собирает **все**
   кластеры (у кластера без данного прохода берётся ближайший по номеру).
5. **Уникальность id**: новые узлы/рёбра кластера получают префикс
   (`namespaceTrees`); существующие узлы и точки подключения сохраняют id.
6. **Глобальный ремонт** меж-кластерных пересечений (`repairMergedCrossings`)
   на локальной маске; при слишком большом охвате — пропуск с предупреждением.

## Последствия

- На проверочных наборах (один кластер) поведение идентично прежнему.
- **По умолчанию выключено**: локальная дискретизация кластера меняет фазу
  ячеек и может сменить канонический выход точки (FR-43/E43) или дать
  остаточные меж-кластерные дефекты. Режим предназначен для очень крупных
  наборов и требует отдельной валидации; включается `forest-decomposition=true`.
- Открытый вопрос (follow-up): сохранение канонического выхода при
  альтернативном выборе в кластере и полный ремонт степени/пересечений между
  кластерами.
