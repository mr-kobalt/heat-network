# Алгоритм (предлагаемый подход)

> Статус: проектное предложение. Уточняется по мере реализации; значимые
> изменения фиксируются в [adr/](adr/). Основа — ADR-0006 (эвристика).
> Учтены уточнения протокола встречи 16.09.2026 (помечены «(протокол)»).

## 1. Формулировка

Требуется построить лес (набор деревьев), соединяющий подмножество
перспективных ОКС с существующей сетью в одной или нескольких точках врезки,
минимизируя `S = 0.7·(C/25e6) + 0.3·(L/100)` при ограничениях:

- обход запретных зон (с минимальными расстояниями);
- спецпроходы для допустимых пересечений (угол, глубина, `Kспец`);
- расход и Ду зависят от набора ОКС на общем участке;
- предельная длина непрерывной части одного Ду (+1 номенклатура при превышении);
- степень камеры ≤ 4 (1 + ≤3);
- отсутствие замкнутых маршрутов;
- минимизация числа поворотов; нестандартные углы дороже;
- геометрия без зигзагов и самопересечений.

Это **ограниченный лес Штейнера** с нелинейной (кусочно-постоянной) функцией
стоимости от потока. Задача NP-сложна → используем многоэтапную эвристику
(ADR-0006), а не точный решатель.

## 2. Подготовка данных

1. `ingest`: потоковый разбор, валидация, классификация; невалидная геометрия →
   диагностическая ошибка (протокол).
2. CRS: перепроецирование 4326 → 32637 (метры).
3. Индексы: R-tree/SpatialIndex (JTS) по препятствиям, сети, ОКС.

## 3. Модель препятствий

- **Запретные** объекты буферизуются на минимальное горизонтальное расстояние,
  зависящее от Ду нового участка (5/7/9 м для ОКС; 1,0–2,0 м для прочих).
- **Допускаемые** объекты (спецпроход) не исключают пространство, но:
  - угол пересечения считается от **оси препятствия** (ось строит команда);
  - для полигональных объектов расстояние — от внешней границы полигона;
  - для линейных — между внешними границами расчётных габаритов (таблица 4.2);
  - для дорог и трамвайных путей — 3 м за границей/буфером;
  - пересечение под углом ≥45° (road, tram_tracks);
  - сегмент внутри зоны выделяется как `laying_method = special` с `Kспец`;
  - при наложении зон нескольких препятствий — **максимальный** `Kспец`,
    один спецучасток на весь участок, без перемножения (протокол);
  - проверяется глубина/просвет (Phase 2).
- Правила задаются конфигом (ADR-0009), а не хардкодятся.

## 4. Кандидаты узлов

- точки подключения ОКС (`oks_connection_point`) — цель маршрута; геометрия ОКС
  не используется (протокол);
- точки существующей сети: камеры, концы участков, сэмплы вдоль линий
  (для кандидатов врезок);
- вершины препятствий/их буферов (для обхода);
- точки кластеризации (общие стволы).

## 5. Граф поиска и маршрутизация

1. **Граф видимости** между кандидатами: ребро допустимо, если отрезок не
   пересекает запретные буферы (или пересекает только допустимые зоны).
   Взвешивание — длина × множители (спецпроход, нестандартный угол).
2. **A*/Dijkstra** от группы ОКС до множества кандидатов врезок.
3. **Кластеризация ОКС** для совместного подключения; стволы соединяют
   кластеры к одной врезке.
4. **Слияние маршрутов**: при пересечении двух маршрутов вне узла — объединение
   в общий ствол либо перестроение (FR-29).

## 6. Расход, Ду, предельная длина

- Поток на рёбрах — сумма расходов ОКС, подключённых «ниже» по дереву.
- `selectDiameter(flow)`: минимальный Ду с пропускной способностью ≥ расхода.
- Разбиение дерева на непрерывные части одного Ду; проверка предельной длины.
- При превышении предельной длины допускается поднять Ду на одну номенклатуру
  (200 → 250), не более (протокол).
- При разветвлении без смены Ду длина суммируется по номенклатуре; при разных
  Ду — считается отдельно (протокол).
- Обновление узлов: камеры в ветвлениях/врезках, технические узлы при смене Ду.

## 7. Камеры, ветвления, врезки

- Новая тепловая камера **обязательна в каждой точке разветвления** (протокол).
- ≤4 примыкающих участка (1 к источнику + ≤3 других).
- Логической разницы между камерой, техузлом и врезкой нет: камера — узел
  с несколькими лучами, врезка — новый единственный луч (протокол).
- Если точка врезки в пределах 10 м от существующей камеры — врезка в камеру;
  при нескольких камерах в радиусе 10 м — оптимальная по стоимости (протокол).
- Несколько новых веток к одной камере — несколько независимых врезок (протокол).
- При превышении числа лучей — перенос ветвления, новая камера или перестроение.

## 8. Реконструкция

1. Для каждой врезки распространить `Gнов` по `upstream_object_id` к источнику.
2. Суммировать вклады на общих существующих частях.
3. `Gитог = Gсущ + Gнов`, подбор требуемого Ду.
4. Если `Ду_треб > Ду_сущ` — создать объект реконструкции с фактической частью
   (только часть отрезка) (протокол).
5. Проверить реконструкцию используемых камер; прочие камеры не реконструировать.
6. Геометрию существующей сети не проверять (протокол).

## 9. Стоимость и ранжирование

Единый `CostModel`:
- участки: `L·cнов(Ду)·Kгл·Kспец`;
- нестандартный угол отвода (не 45°/90°) — ×1,5 и минимизация поворотов (протокол);
- камеры и врезки по шкалам;
- реконструкция: `Lрек·cрек(Ду_треб)`;
- штрафы за неподключённые ОКС.
Затем `S` и сортировка. Расстояния округляются в большую сторону при
незначительном отклонении (протокол).

## 10. Генерация вариантов (до трёх)

Содержательно разные варианты получаются сменой:
- набора/мест точек врезки;
- разбиения ОКС на кластеры (совместно/раздельно);
- маршрутов (разные обходы);
- способа прохождения ограничения (если допустимо несколько).

Механизм: несколько прогонов эвристики с разными параметрами/seed и отбор
различающихся решений; смещение одной трассы вариантом не считается (FR-75).

## 11. Неполный результат

Маршрутизация изолирована по ОКС/кластерам: сбой одного не рушит остальные.
Не подключённые ОКС попадают в `unconnected_oks_ids`, штраф учитывается.
Неподключение допускается при дороговизне трассы (протокол).

## 12. Детерминизм и производительность

- Фиксированный seed, детерминированные сортировки — воспроизводимость.
- Масштаб: тысячи объектов, вход до 2–3 ГБ; расчёт офлайн, один экземпляр
  (протокол). Быстродействие — дополнительный критерий, жёсткого лимита нет.
- Инкрементальный расчёт стоимости, кэширование геометрии.
- Потоковый ввод/вывод (ADR-0008); ограничение памяти.

## 13. Расширение 2.5D (Phase 2)

- Состояние узла = (x, y, depth); глубина — параметр (шага 0,5 м нет, протокол).
- Переходы: наклонные участки с уклоном ≤0,10 м/м.
- Пересечения: выбор «выше/ниже» по стоимости, проверка просветов; близкие
  пересечения можно объединять в один подход без возврата на 3,0 м (протокол).
- `Kгл = 1 + 0.10·(h−3)`; на наклонах — среднее коэффициентов.
- Минимум 0,7 м — минимальное отклонение по глубине от препятствия (протокол).
- Если решение не найдено — пометка о ручной проработке.

## 14. Почему не точная оптимизация

Точные MILP/ILP-модели возможны, но при тысячах объектов и большом объёме
входа не укладываются в ресурсы и время, а также требуют дискретизации
геометрии. Эвристика даёт приемлемое качество и объяснимость; отдельные
подзадачи (подбор Ду, стоимость) остаются точными.
