# Дорожная карта

Вехи соответствуют требованиям к сдаче (PDF 7). Каждая веха имеет
измеримый критерий готовности. Задачи — в [backlog.md](backlog.md).

## M0. Фундамент (текущая фаза) — завершена

**Цель:** зафиксировать объём, контекст и среду разработки.

Состав:
- репозиторий, `.gitignore`/`.gitattributes`/`.editorconfig`;
- devenv: Java 11, Maven, PostgreSQL + PostGIS, скрипты, `devenv test`;
- каркас Spring Boot 2.6.3 (Maven), health/info, OpenAPI, профили;
- Dockerfile и docker-compose;
- проектная документация и ADR.

Критерий готовности:
- `devenv test` — успех; `mvn test` — успех; `docker compose config` — валиден;
- документация создана и связана.

## M1. Прототип / промежуточная сдача (PDF 7.1) — выполнено

**Цель:** работающий прототип загрузки данных и построения части сети.

Реализовано: потоковая загрузка GeoJSON и API (`/datasets`, `/runs`),
разбор всех типов и диагностика, CRS 4326↔32637, граф существующей сети,
конфигурируемые ограничения, маршрутизация с обходом запретных зон,
подбор Ду и стоимость, выгрузка GeoJSON, асинхронный расчёт, PostgreSQL
(`schema.sql`), опциональный фронтенд-визуализатор (ADR-0013).
На образце подключены все 17 точек (см. `CalculationPipelineTest` и
проверку API). Осталось: отчёт «реализовано / риски / план» и демонстрация.

Состав:
- потоковая загрузка GeoJSON (FR-01, FR-07) и API;
- разбор всех типов объектов и атрибутов (FR-04, FR-05);
- CRS 4326 → 32637 (FR-03);
- граф существующей сети по `upstream_object_id` (FR-10, FR-11);
- модель препятствий и базовый обход (FR-50, FR-51);
- построение хотя бы части новой сети до существующих ОКС;
- диагностика входных данных (FR-08).

Критерий готовности:
- на `source/data_example.geojson` сервис строит сеть хотя бы для части точек
  подключения и выгружает валидный GeoJSON;
- краткий отчёт «реализовано / риски / план».

## M2. Обязательная 2D-задача end-to-end — реализовано в редакции ТП v2

**Цель:** полное соответствие обязательному функционалу (ТП v2).

Реализовано (эпик E13): базовый вход без `oks_future`/`oks_existing`
(ОКС = `restriction=oks`), ID string|number, присоединение только через камеру
и счёт примыканий (проходная линия = 2), Ду+предельная длина по непрерывным
путям, `railway` — запрет, спецпроход одним прямым участком, финальный коридор
в `oks`, отказ от реконструкции, новый состав вывода/сводки. Прогон на
`source/Датасет скорректированный.geojson`: все 17 точек подключаются.
Остаётся проверка на проверочном наборе (M5).

Состав:
- автовыбор места присоединения через камеру (FR-21, FR-22, FR-27, FR-33);
- совместное/раздельное подключение, общие стволы (FR-23, FR-24);
- ветвления в камерах, ≤4 примыканий (FR-25, FR-26);
- спецпроходы одним прямым участком, угол, `Kспец` (FR-52…FR-57);
- финальный прямой участок в `oks` (FR-32);
- расходы, подбор Ду совместно с длиной по путям (FR-40…FR-48);
- стоимость участков, камер (включая присоединение), врезок в существующие
  камеры, штрафы (FR-70…FR-74, FR-81, FR-82);
- до трёх вариантов и ранжирование (FR-75, FR-76);
- частичный результат (FR-77);
- полная выгрузка GeoJSON по v2 (FR-78…FR-85);
- без реконструкции и `tie_in` (FR-18, FR-33).

Критерий готовности:
- результат на проверочном наборе проходит обязательные проверки;
- стоимость, длины и примыкания считаются согласованно;
- варианты различаются содержательно и ранжируются.

## M3. Качество и производительность

**Цель:** стабильность и универсальность (NFR-09, NFR-10).

Состав:
- устойчивость на другом наборе без изменения алгоритма;
- диагностика; невалидная геометрия → диагностическая ошибка;
- потоковый ввод 2–3 ГБ / вывод 500 МБ (NFR-08), тысячи объектов;
- нагрузка до 50 пользователей (NFR-07) в единственном экземпляре;
- быстродействие как дополнительный критерий;
- офлайн-режим и headless-профиль (NFR-12, NFR-13);
- постобработка геометрии (без зигзагов и самопересечений).

Критерий готовности:
- прогон на другом наборе без правок кода;
- отсутствие деградаций по памяти/времени.

## M4. Дополнительный режим по глубине (не обязателен)

**Цель:** 2.5D-трассировка (ТП 5).

Состав:
- отдельный режим и отдельный набор вариантов (не смешивается с 2D);
- глубина как атрибуты `depth_start`/`depth_end`, без Z-координат;
- глубина 3,0/0,7 м; уклон ≤0,10 м/м; `Kгл`, средние коэффициенты;
- профиль спуск/постоянная/возврат; техузел при переходе 3,0 м;
- сохранение изменённой глубины между близкими препятствиями.

Критерий готовности:
- отдельный режим с учётом глубины проходит демонстрацию.

## M5. Финальная сдача (PDF 7.2)

Состав:
- презентация по 10 пунктам (PDF 4);
- сопроводительная документация по 5 пунктам (PDF 5);
- выгрузка результата на проверочном наборе из рабочих систем;
- репетиция питч-сессии;
- учёт двух этапов оценки: горизонтальные проекции, затем Z/глубины (протокол).

Критерий готовности:
- работающий сервис, презентация, документация, результат.
