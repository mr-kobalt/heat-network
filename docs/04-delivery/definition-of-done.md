# Definition of Done (DoD)

Задача считается выполненной, когда все пункты ниже истинны. Для
исследовательских/документарных задач применимы релевантные пункты.

## 1. Код

- Реализовано согласно требованиям (FR/NFR) и правилам ТП.
- Нет хардкода координат, ID, конфигурации набора (NFR-09).
- Код читаемый, следует соглашениям из
  [glossary.md](../02-domain/glossary.md) и `.editorconfig`.
- Нет мёртвого/закомментированного кода, секретов в репозитории.

## 2. Тесты

- Есть unit-тесты на новую логику расчёта; негативные сценарии покрыты.
- `mvn test` проходит локально и в CI (если есть).
- Для изменений правил — тесты, привязанные к таблицам ТП.

## 3. Сборка и окружение

- `mvn -DskipTests package` и `mvn test` — успех.
- `devenv test` — успех.
- При изменении инфраструктуры — `docker compose config` валиден.

## 4. Документация

- Обновлены затронутые документы (`requirements`, `data-model`,
  `calculation-rules`, `algorithm`).
- Архитектурные решения зафиксированы ADR.
- Изменения объёма отражены в уставе/дорожной карте.

## 5. Интеграция

- API-контракт (Swagger) актуален.
- Выходной GeoJSON соответствует [data-model.md](../02-domain/data-model.md).
- Диагностика входных данных не роняет сервис; невалидная геометрия даёт
  понятную ошибку.
- Нет исходящих сетевых вызовов (офлайн) и нет UI/фронтенда в поставке.

## 6. Ревью

- Изменение просмотрено (человеком или агентом-ревьюером).
- Нет открытых блокирующих замечаний.
