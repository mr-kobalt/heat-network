# Правила расчёта

Извлечено из `source/Техническое  приложение ЛЦТ v2.docx` (актуально) с
уточнениями `source/Разъяснения по вопросам ЛЦТ.docx` и протокола встречи
16.09.2026. Это справочник для реализации; значения выносятся в
конфигурацию/константы, а не «зашиваются» в логику (ADR-0009).

> При расхождении приоритет за ТП v2 и разъяснениями.

## 1. Базовые правила новой сети (ТП 2.1)

- Базовый способ — подземная бесканальная прокладка.
- Один линейный объект = пара подающего и обратного трубопроводов одного Ду.
- Расход пары не удваивается; для расчёта используется один расход пары.
- Расход участка = сумма расходов точек подключения, расположенных далее.
- Для каждого узла, где меняется расход, Ду сохраняется на всей длине до
  следующего такого узла; менять Ду только для нового отсчёта длины нельзя.
- Ду от точки подключения к месту присоединения не уменьшается.
- Ветвления — только в тепловых камерах; ≤4 примыкающих линейных участков.
- Существующая линия, проходящая через камеру и разделённая ею, занимает
  **два** примыкания (разъяснение 12).
- Поворот без изменения параметров — вершина `LineString`, отдельного узла не
  требует; угол — от продолжения предыдущего участка, произвольный до 90°
  включительно, **без удорожания** (разъяснение 5). В тепловой камере угол между
  **любой парой** примыкающих участков — **не менее 30°** (проверяется попарно,
  независимо от маршрута); маршрутные повороты (внутренние вершины, технические
  узлы) остаются ≤ 90°.
- Технический узел (`technical_node`) — только при смене способа прокладки,
  профиля глубины или иного параметра без разветвления; стоимости не имеет.
- Трасса без необоснованных изломов, зигзагов и ступеней.
- Новые участки не пересекаются между собой вне общего узла (FR-29).

Правила:
- Выбирается **минимальный Ду, одновременно удовлетворяющий** расчётному
  расходу и предельной длине (разъяснение 1).
- Предельная длина проверяется отдельно по каждому непрерывному пути; общий
  участок учитывается в каждом пути; длины параллельных ветвей не суммируются
  (разъяснение 2).
- Камера/технический узел без смены Ду новый отсчёт не начинают; смена Ду —
  начинает.
- Произвольное завышение Ду не допускается.
- Если расход превышает пропускную способность максимального Ду (1400 мм) —
  диагностика.

### 2.1. Расчётный габарит (ТП 3.1)

- Линия новой сети — ось пары труб; внешняя граница на половине ширины пары.
- Для полигонального ограничения расстояние — от границы полигона до внешней
  границы габарита новой сети.
- Для линейного ограничения — от его геометрии до внешней границы габарита.
- Если у ограничения собственный габарит — между внешними границами габаритов.

## 4. Пространственные ограничения (ТП 4)

- Для линейных ограничений входная геометрия — ось объекта.
- Специальный проход — **один прямой участок**; на границах участок делится;
  если граница не совпадает с камерой/точкой подключения — создаётся
  `technical_node`.
- Минимальное горизонтальное расстояние применяется при прохождении рядом;
  **внутри** разрешённого специального пересечения не проверяется.
- Угол пересечения: для линейного ограничения — относительно его линии; для
  полигонального — в точке входа специального участка относительно
  пересекаемой границы.
- При наложении специальных проходов: выполняются все геометрические
  требования; для стоимости — **наибольший** `Kспец`, без суммирования и
  перемножения; на границах общего фрагмента — новый участок; каждое отдельное
  пересечение одного объекта — отдельный специальный проход.
- В обязательной части — типы таблицы 2; прочие допустимы как расширение.

| Объект | Правило | Мин. гориз. расстояние | Угол | Kспец |

- Для дорог и трамвайных путей границы спецучастка — полигон и по 3 м за
  границей с каждой стороны.
- Для газопровода/кабеля/существующей сети границы спецпрохода — по 2 м с
  каждой стороны от точки пересечения (в режиме глубины — условия по
  вертикали; см. §6).
- Способ прокладки (`laying_method`): `base` / `special`.
- **Строгий обход (E25/ADR-0045, флаг `forest-special-strict`):** полоса
  `minDistance + halfPairWidth` вокруг спецобъекта непроходима; пересечение —
  только через «ворота», перпендикулярные оси (угол ≈90° ≥45°); движение вдоль
  полосы запрещено. `heat_network` не блокируется (цель врезки). Дефолт флага —
  off до калибровки. `Kспец` входит в целевую функцию поиска (E25-04), выпрямление
  спецучастка через запрет не допускается (E25-06), клетки источников открываются,
  строгие полосы объединяются (`carveUnion`, E25-07). Полосы — по минимальному Ду;
  учёт фактического Ду — флаг `forest-diameter-aware-buffers` (E25-05b).
- **Спецпроход — по пересечению, прямой (E32/E38/E41):** спан — участок трассы
  внутри спецзоны при фактическом пересечении оси/границы; движение вдоль
  препятствия спецпроходом не считается. Строгая полоса покрывает **всю**
  спецзону (`zoneBufferM + halfPairWidth`), пересечение — только через
  перпендикулярные «ворота»; угол ≥ `angle-min-deg` проверяется жёстко
  (`angleOk`). Выпрямление спецчанка в один прямой отрезок безусловно (внутри
  пересечения мин. расстояние не проверяется). Дороги на входе — полигоны
  (E31, ширина ≤6 м).

### 4.1. Подход к точке подключения в полигоне ОКС (ТП 2.2)

- `oks`-полигон непроходим с отступом (5/7/9 м по Ду).
- Для полигона, содержащего целевую `oks_connection_point`, допускается **один
  финальный прямой участок** от точки до канонической точки выхода за внешней
  границей буфера; требование отступа к собственному полигону на этот участок
  не распространяется. Остальные ограничения действуют.
- **Правило точки выхода** (ADR-0032):
  1. `designDiameterMm` — минимальный Ду под `flow_tph` самой точки
     (`DiameterCatalog.select`); от него зависят отступ и габарит.
  2. Фигура ОКС — **выпуклая оболочка** `oks`-полигона.
  3. От точки — перпендикуляр к ближайшему ребру оболочки; в его продолжении на
     расстоянии `minDistance(oks, designDiameterMm) + halfPairWidth(designDiameterMm)`
     — точка выхода.
  4. Точка выхода и финальный отрезок не должны попадать в буферы чужих
     ограничений; иначе точка не подключается.
  5. Точка вне `oks`-полигона — выход совпадает с точкой подключения.
- Перебор нескольких перпендикуляров, «выход из кармана» и проверка
  достижимости кандидатов не применяются. Запас `oks-exit-clearance-m` и
  `oks-approach-policy` относятся только к прежней ветке `mst` (ADR-0024) и
  временно сохранены для неё.
- Несколько точек в одном полигоне — самостоятельные цели.

## 5. Присоединение к существующей сети (ТП 2.4)

> На период разработки нового алгоритма единого леса (ADR-0031) выбор точки
> врезки **временно ослаблен**: допускается любая точка `heat_network` или
> существующая камера, без правила 10 м и без лимита примыканий; действующий
> алгоритм `mst` продолжает работать по полным правилам. Ослабление снимается
> до конкурсной поставки.

- Присоединение — **только через тепловую камеру**; отдельного объекта `tie_in`
  нет.
- Если выбранная точка ≤10 м от существующей `heat_chamber` и после
  подключения к ней будет ≤4 примыканий — используется существующая камера;
  новый участок заканчивается в ней.
- Иначе новая `heat_chamber` создаётся в выбранной точке существующего
  `heat_network`; отдельного геообъекта места присоединения нет.
- Точка врезки — **любая точка `heat_network`** (непрерывно): при выборе
  рассматриваются точные проекции анкера на участки, а не дискретная сетка
  30 м (сэмплы сохранены как дополнительный источник; ADR-0026). Правило 10 м
  проверяется относительно выбранной точки.
- При нескольких подходящих существующих камерах выбирается одна.
- Существующая сеть и камеры не реконструируются; текущий расход и резерв не
  определяются.

## 6. Глубина (дополнительный режим, ТП 5)

- Режим не обязателен; базовый 2D сохраняется.
- Отдельный режим (`mode=depth`) и отдельный набор вариантов; результаты не
  объединяются в одно ранжирование (ADR-0073).
- Условная горизонтальная поверхность; глубина до верхней границы габарита.
- Обычная глубина 3,0 м; минимальная 0,7 м; максимальная и шаг не задаются.
- Уклон ≤0,10 м/м (на 1 м глубины ≥10 м по горизонтали).
- Профиль: спуск/подъём, постоянная глубина, возврат.
- `Kгл = 1` при `h ≤ 3`; `Kгл = 1 + 0,10·(h−3)` при `h > 3`; на уклоне —
  среднее коэффициентов.
- При пересечении уровня 3,0 м — `technical_node` и деление участка.
- Для стоимости и предельной длины — длина по горизонтальной проекции.

### 6.1. Реализация (ADR-0073)

- Вертикальный **пост-слой** над 2D-планом (маршрут переиспользуется).
- Вертикально значимые типы и габариты (таблица 4): газопровод — верх 2,8 м,
  высота 0,40 м; силовой кабель — 2,7 м, 0,20 м; существующая теплосеть —
  3,0 м, высота по габариту пары. Задаются в правилах ограничений
  (`vertical-top-depth-m`, `vertical-height-m`).
- Где габарит новой сети конфликтует с обычной отметкой, профиль уходит
  **выше** (предпочтительно, `Kгл = 1`, не ниже 0,7 м) либо **ниже** (кабель
  и т. п.); зазор — `heating.app.depth-vertical-clearance-m` (**допущение**: ТП
  чисел не задаёт).
- Близкие пересечения (зазор ≤ `depth-close-crossing-m`) объединяются без
  возврата на 3,0 м — **допущение вместо NQ-05**.
- Границы участков профиля (спуск↔полка↔возврат) — `technical_node` (FR-30).
- Неизвестные/неполные габариты типов вертикально не учитываются (диагностика
  `DEPTH_OBSTACLE_UNRESOLVED`); при нехватке длины на уклон —
  `DEPTH_SLOPE_EXCEEDED`.
- Ограничение E9-06: профиль считается по ребру (на границах — возврат на
  3,0 м), а не по непрерывному пути дерева; интеграция в поиск пути — E9-05.

## 7. Реконструкция — удалено (ТП v2)

Реконструкция существующей тепловой сети и существующих камер в актуальной
модели не выполняется: пространственные ограничения, коэффициенты и деление
участка для реконструкции не рассчитываются (разъяснение 14). Правила прежней
редакции (FR-60…FR-67) не применяются.

## 8. Камеры и врезки (ТП 3.2, 2.4)

- К камере ≤4 примыкающих линейных участка; существующая линия, разделённая
  камерой, — 2 примыкания.
- Каждый линейный участок, геометрически заканчивающийся в камере, — отдельное
  примыкание.
- Стоимость новой камеры — по наибольшему Ду примыкающих участков, **включает
  присоединение к существующей сети**; отдельной стоимости врезки при новой
  камере нет.

| Наибольший Ду, мм | Стоимость новой камеры, руб. |
|-------------------|------------------------------:|
| 50–200 | 3 000 000 |
| 250–500 | 5 000 000 |
| 600–1000 | 8 000 000 |
| 1200–1400 | 12 000 000 |

- Присоединение к существующей камере — **5 000 000 руб. за каждый** новый
  линейный участок, заканчивающийся в ней.

## 9. Стоимость (ТП 6)

- Обычный участок: `Cуч = L · cнов(Ду) · Kгл`.
- Специальный: `Cуч = L · cнов(Ду) · Kгл · Kспец`.
- Для 2D `Kгл = 1`; удорожания поворотов нет.
- При наложении препятствий — максимальный `Kспец`, без перемножения.
- `construction_cost` = новые участки + новые камеры + врезки в существующие
  камеры (5 000 000 за участок).
- `calculated_cost = construction_cost + unconnected_penalty`.
- Штраф за точку: `Ш = 100 000 000 + 500 000 · G`.

## 10. Ранжирование (ТП 6)

```
S = 0,7 · (C / 25 000 000) + 0,3 · (L / 100)
```

- `C` — `calculated_cost`, руб.
- `L` — `new_network_length` (суммарная длина новых участков), м.
- Меньше `S` — выше вариант. До трёх вариантов на режим.

## 11. Округление и диагностика

- Расстояния округляются в большую сторону при незначительном отклонении
  (4,999 → 5 м); допуск — `rounding-tolerance-m` (допущение, ТП v2 молчит).
- Невалидная геометрия на входе → диагностическая ошибка.
- Неподключение — только при отсутствии допустимого маршрута (разъяснение 15).

## 12. Замечания для реализации

- Таблицы — единый источник правды; не дублировать значения в коде.
- `restriction_type`, не входящие в таблицу 2, — необязательное расширение.
- `Kспец`/`Kгл` применяются к стоимости, не к длине и не к Ду.
