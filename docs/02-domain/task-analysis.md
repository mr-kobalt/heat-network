# Анализ задачи

Сжатое изложение кейса (`source/2. ДИТ.pdf`) с уточнениями протокола встречи
16.09.2026 (`source/`). Полные правила расчёта —
в [calculation-rules.md](calculation-rules.md), форматы —
в [data-model.md](data-model.md).

> Уточнения протокола помечены «(протокол)».

## 1. Контекст

Новые здания нужно подключать к системе теплоснабжения. Подключение —
часть технологического присоединения: для каждого объекта определяют место
подключения и маршрут прокладки сети в плотной городской застройке. При
нескольких перспективных ОКС число вариантов быстро растёт (совместное или
раздельное подключение, разные точки врезки и маршруты). Ручной перебор
трудозатратен — нужна автоматизация.

## 2. Как формирует вариант инженер (что автоматизируем)

1. Тепло идёт по паре труб (подающая + обратная) одного Ду; на карте — одна линия.
2. Точка подключения ОКС находится на границе здания (ИТП внутри не уточняется).
   По протоколу даётся **конкретная точка подключения**, а геометрия ОКС на
   маршрут **не влияет**.
3. Выбирается точка врезки в существующую сеть: в существующей камере либо в трубопроводе.
4. Строится маршрут от существующей сети к ОКС; несколько ОКС могут использовать
   общий участок с последующим разделением.
5. Учитываются препятствия: обход, минимальные расстояния, спецпроходы.
6. Определяется расход на каждом участке (сумма по подключённым ОКС), подбирается Ду.
7. Сравниваются варианты; длина — не единственный критерий (короткий маршрут
   может быть дороже из-за врезки, препятствий, дополнительных сооружений).

## 3. Упрощения базовой модели

- Один источник; ограничение мощности не рассматривается; сеть связана с источником.
- Для существующих участков заданы Ду, расход и `upstream_object_id`.
- Для ОКС заданы тепловая нагрузка и готовый расчётный расход.
- Одна линия = пара труб одного Ду.
- Каждая часть новой сети присоединяется к существующей в одной точке.
- От врезки до каждого ОКС ровно один путь (без замкнутых маршрутов).
- Вся проектируемая сеть — магистральная.
- Обязательная часть — 2D; глубина — в дополнительной задаче (второй этап оценки).
- Прокладка подземная бесканальная; надземная не рассматривается.
- К источнику Ду и пропускная способность существующей сети не уменьшаются;
  полный гидравлический расчёт не выполняется.
- Геометрия существующей сети не проверяется (протокол).
- Масштаб: тысячи объектов в масштабе города; объём данных до 2–3 ГБ (протокол).

## 4. Структура новой сети

- Общие участки для нескольких ОКС (суммарный расход), разделение после ветвления.
- Разветвления — в тепловых камерах; ≤4 примыкающих участка (1 к источнику + ≤3 других).
- Новая тепловая камера **обязательна в каждой точке разветвления** (протокол).
- Логической разницы между тепловой камерой, техническим узлом и врезкой нет:
  камера — узел с несколькими лучами, врезка — новый единственный луч (протокол).
- Технические узлы — в точках смены параметров, без собственной стоимости.
- Геометрия: прямые отрезки, рациональные повороты, минимизация поворотов;
  без зигзагов и ступеней.
- Новые участки не пересекаются между собой вне общего узла.

## 5. Расходы и диаметры

- Расход ОКС берётся готовым; на общем участке расходы суммируются;
  учитывается расход подающего трубопровода.
- Для участка — минимальный подходящий Ду по таблице пропускных способностей.
- Вместо гидравлики — предельная длина непрерывной части одного Ду:
  камеры/узлы отсчёт не сбрасывают, смена Ду — сбрасывает.
- При превышении предельной длины допускается увеличить Ду на одну
  номенклатуру (200 → 250), не более (протокол).
- При разветвлении без смены Ду протяжённость суммируется по номенклатуре;
  при разных Ду считается отдельно (протокол).

## 6. Проверка существующей сети

- Дополнительный расход от врезки добавляется к расходу участка врезки и далее
  ко всем участкам по направлению к источнику.
- Расходы нескольких подключений на общей части суммируются.
- Для затронутых участков: `Gитог = Gсущ + Gнов`, подбор Ду; если требуемый Ду
  больше существующего — участок реконструируется (геометрия не меняется,
  реконструируется только часть отрезка).
- Для камеры: сравнивается максимальный примыкающий Ду с исходным; при превышении —
  реконструкция (учитывается один раз). Камеры, не являющиеся точками врезки,
  не реконструируются и в стоимость не включаются (протокол).
- Геометрия существующей сети не проверяется (протокол).

## 7. Ограничения

Для каждого типа — либо запрет пересечения (обход с минимальным расстоянием),
либо допустимый специальный проход с условиями (расстояние, угол, глубина,
границы спецучастка, коэффициент стоимости `Kспец`).

Уточнения (протокол):
- угол пересечения считается от **оси препятствия** (ось строит команда);
- для полигональных объектов расстояние — от внешней границы полигона;
  для линейных — между внешними границами расчётных габаритов;
- для дорог и трамвайных путей — 3 м за границей/буфером;
- при наложении зон нескольких препятствий берётся **максимальный коэффициент**,
  один спецучасток на весь участок, без перемножения;
- правила — по СП «Тепловые сети»; организаторы готовы консультировать.

См. таблицу 5.1 в [calculation-rules.md](calculation-rules.md).

## 8. Стоимость

Учитываются: новые участки, новые камеры, врезки, спецпроходы, реконструкция
участков и камер, штраф за неподключённые ОКС.
Дополнительно (протокол):
- нестандартные углы отвода (не 45°/90°) → удорожание ×1,5 и минимизация поворотов;
- при наложении препятствий — максимальный коэффициент, без перемножения;
- расстояния округляются в большую сторону при незначительном отклонении.
Формулы — в [calculation-rules.md](calculation-rules.md).

## 9. Варианты и ранжирование

Основной вариант + до двух содержательно отличающихся. Отличие — смена точки
врезки, объединения ОКС, маршрута, разбиения на части, способа прохождения
ограничения. Небольшое смещение трассы вариантом не считается.
Ранжирование — по `S = 0.7·(C/25 000 000) + 0.3·(L/100)`.

## 10. Неполный результат

Конкурсный набор подготавливается так, чтобы все ОКС подключались. Но сервис
обязан обработать случай, когда маршрут для отдельного ОКС не найден: сохранить
частичный результат и вывести перечень ID (`unconnected_oks_ids`).
Неподключение допускается при дороговизне трассы — работает система штрафов
(протокол).

## 11. Дополнительная задача по глубине

Самостоятельная задача: маршрут строится заново с учётом плана и глубины.
Условная горизонтальная поверхность Z=0; глубина — до верхней границы габарита.

Уточнения (протокол):
- шага 0,5 м в актуальном приложении **нет**;
- минимум 0,7 м — это минимальное **отклонение по глубине** от пересекаемого
  препятствия;
- обычная глубина 3,0 м; удорожание за каждую дополнительную величину заглубления;
- близкие пересечения разрешено объединять в один подход без возврата на 3,0 м
  (критерий близости уточняется).

## 12. Этапы и критерии оценки

- Веса: протяжённость 0,3, стоимость 0,7.
- Два этапа (протокол): сначала сравниваются горизонтальные проекции с эталонной
  геометрией; Z и расчёты углублений — только на втором этапе (до 10 решений).
- Дополнительные плюсы: обоснованные критерии стоимости, вариативность
  препятствий (метро, детсады, школы, водные преграды, трамвай), универсальность
  алгоритма под другие ресурсы (водоснабжение, кабели).
