# AGENTS.md

Краткая точка входа для AI-агентов. Подробности — в `docs/`.

## Проект

Сервис автоматического построения трасс подключения перспективных ОКС
к существующей тепловой сети (кейс ЛЦТ 2026). Вход и выход — GeoJSON.
Текущий этап: фундамент + **M1** — рабочий прототип (потоковый ввод,
диагностика, граф существующей сети, ограничения, частичная маршрутизация,
выгрузка GeoJSON, REST API, PostgreSQL) и опциональный фронтенд-визуализатор.

## Стек (обязательный, не менять без ADR)

Java 11 · Spring Boot 2.6.3 · Maven · PostgreSQL + PostGIS ·
springdoc-openapi-ui 1.7.0 · JTS · docker-compose. Ubuntu Server 22.

## Команды

```bash
devenv shell                       # Java 11 + Maven + Node/pnpm
db-up                              # PostgreSQL + PostGIS (docker-compose)
mvn -B -DskipTests compile         # компиляция
mvn -B test                        # тесты
mvn -B verify                      # полная проверка
devenv test                        # smoke окружения
docker compose config              # если менялась инфраструктура
pnpm --dir frontend dev            # визуализатор (dev)
pnpm --dir frontend build          # сборка визуализатора
```

## Жёсткие правила

- Соблюдать требования ТП, а не `source/data_example.geojson` (он неполный).
- Исходные материалы (ТЗ, ТП, датасет, протокол встречи) — в `source/`.
- Не хардкодить координаты, ID и конфигурацию набора.
- Потоковая обработка больших файлов (вход 3 ГБ, выход 500 МБ).
- Правила ограничений — конфигурируемые (ADR-0009).
- Не коммитить и не пушить без явного запроса.
- Архитектурные решения — через ADR; объём — через устав/дорожную карту.
- Перед завершением задачи: компиляция + тесты + обновление документации.
- Сервис headless (без UI); UI и фронтенд не добавлять в ядро (ADR-0010).
- Фронтенд в `frontend/` — опциональный визуализатор вне оцениваемой поставки (ADR-0013).
- Решение только на Java 11; расчёт офлайн, единственный экземпляр (ADR-0012).
- Каждый изменённый документ — с разделом «История изменений».
